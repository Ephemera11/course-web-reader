课程 0006 · 连接、会话与心跳

MQTT 深入 · 第 6 课 · 预计 14 分钟

MQTT 是长连接协议：客户端连接后保持 TCP，Broker 需要知道你还活着。这一课讲连接建立流程、会话（离线消息补收的关键）、以及心跳（Keep Alive）怎么让 Broker 判断你死了。

本节目标：能说清 CONNECT/CONNACK 握手、Clean Session 开关的意义、Keep Alive 与遗嘱的配合。

1. 连接建立（握手）

客户端发 CONNECT 报文（含 Client ID、用户名密码、Keep Alive、Clean Session、遗嘱等），Broker 回 CONNACK 确认并带结果码：

Client ID唯一标识，Broker 用它在会话里区分客户端
CONNACK 结果0=接受，1/2/3/4/5=拒绝（协议版本、凭据、未授权等）

2. 会话（Session）与 Clean Session

会话是 Broker 为每个 Client ID 保存的状态：订阅列表 + 未送达消息。

Clean Session=true每次连接全新会话，旧订阅/离线消息全清简单无状态，适合大多数场景
Clean Session=falseBroker 保留会话；重连时恢复订阅、补发离线消息断线续传的关键，弱网设备必备
关键认知：「离线补收」= Clean Session=false + QoS>0。设备断开期间 Broker 暂存 QoS 1/2 消息，重连（同 Client ID）后补发。QoS 0 的消息不暂存。

3. 心跳（Keep Alive）

连接时声明 Keep Alive 秒数（如 60）。客户端必须在间隔内发任何报文（或空 PINGREQ），否则 Broker 判定它「失联」：

// 客户端每 60s 至少发一个 PINGREQ 保活
connect({ keepalive: 60 })

Broker 发现超时未收到任何报文，就断开连接并触发遗嘱——这正是遗嘱消息能被「及时」发出的机制。

4. 弱网设备的推荐姿势

Clean Sessionfalse（保留订阅和离线消息）
Keep Alive30-60s（根据网络质量调）
遗嘱声明离线状态，让系统知道它掉线
断线重连客户端 SDK 自动重连 + 指数退避
