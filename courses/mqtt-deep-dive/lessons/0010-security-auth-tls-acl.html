课程 0010 · 安全：认证、TLS 与 ACL

MQTT 深入 · 第 10 课 · 预计 15 分钟

默认 Mosquitto 是「裸奔」的：任何人在 1883 端口都能连接、订阅、发布。上生产前必须做三层安全加固：认证（你是谁）、加密（内容不泄露）、授权（你能碰哪些 Topic）。

本节目标：能说出安全三要素（认证/加密/ACL），并给 Mosquitto 配上用户名密码。

1. 安全三要素

认证连接时验用户名密码，拒绝陌生人
加密（TLS）消息在传输中加密，防窃听；端口 8883
授权（ACL）控制每个用户能订阅/发布哪些 Topic

2. 第一层：用户名密码认证

# 1) 创建密码文件（交互输入两次密码）
mosquitto_passwd -c /etc/mosquitto/passwd alice

# 2) 编辑配置文件（Windows 在 C:\Program Files\mosquitto\mosquitto.conf）
allow_anonymous false
password_file /etc/mosquitto/passwd

# 3) 重启并测试
mosquitto -v -c /etc/mosquitto/mosquitto.conf
mosquitto_sub -t 'test/#' -u alice -P '密码' -v   # 带凭据才能连
重点：设了 allow_anonymous false 后，没有用户名密码的客户端直接被拒——这是「裸奔→安全」最关键的一步。

3. 第二层：TLS 加密（8883）

需要 CA 证书 + 服务器证书（可用 certbot 免费签发，或内网自签）。配置后客户端改用 ssl://host:8883：

listener 8883
cafile /etc/mosquitto/certs/ca.crt
certfile /etc/mosquitto/certs/server.crt
keyfile /etc/mosquitto/certs/server.key

4. 第三层：ACL 权限控制

# aclfile 配置：alice 只能订阅 device/+/status，不能发布
user alice
topic read device/+/status

# 管理员 admin 全部权限
user admin
topic readwrite #

ACL 是 IoT 安全的精髓：设备只能碰自己的 Topic，即使密码泄露，攻击者也只能访问受限范围。

5. 安全对照速查

开发环境无认证、1883 明文本机调试可以
生产环境匿名全开、明文灾难：任何人可订阅/发布
安全生产认证 + TLS + ACL三层齐全，公网可上线
