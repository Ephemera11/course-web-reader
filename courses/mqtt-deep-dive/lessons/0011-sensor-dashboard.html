课程 0011 · 综合实战：传感器上报 + 实时仪表盘

MQTT 深入 · 第 11 课（收官）· 预计 18 分钟

前 10 课拆开了讲，这一课全部串起来：模拟传感器 → 发布到 Broker → 前端订阅 → 实时仪表盘。做完你就拥有了从「设备数据」到「用户界面」的完整 MQTT 链路。

本节目标：完成一个端到端小项目：Node 模拟传感器发布、浏览器用 MQTT.js 订阅、页面实时更新温度曲线。

1. 架构总览

模拟传感器Node 脚本每秒发布随机温度到 sensor/temp（QoS 1）
Broker本地 Mosquitto（1883）
前端HTML 页面用 MQTT.js 订阅，实时渲染

2. 模拟传感器（Node 发布端）

// sensor.js
const mqtt = require('mqtt');
const c = mqtt.connect('mqtt://localhost:1883');
c.on('connect', () => {
  setInterval(() => {
    const temp = (20 + Math.random() * 10).toFixed(1);
    c.publish('sensor/temp', temp, { qos: 1 });
    console.log('发布:', temp);
  }, 1000);
});

跑 node sensor.js——这就是「设备端」。真实场景里换成 ESP32/树莓派读温度传感器即可。

3. 前端实时仪表盘（HTML + MQTT.js）

<!-- 需要 mqtt.min.js（CDN 或 npm 打包）-->
<script src="https://unpkg.com/mqtt/dist/mqtt.min.js"></script>
<div id="temp" style="font-size:48px">--</div>
<script>
  const client = mqtt.connect('ws://localhost:8083/mqtt'); // WebSocket 桥接
  client.on('connect', () => {
    client.subscribe('sensor/#');
  });
  client.on('message', (t, p) => {
    document.getElementById('temp').textContent = p.toString() + '°C';
  });
</script>
关键点：浏览器不能裸连 MQTT（TCP 1883），要通过 WebSocket 桥接。Mosquitto 加一行配置即可开 WS：listener 8083 + protocol websockets。EMQX 默认支持 ws://host:8083/mqtt。

4. 串起来验证

步骤 1启动 mosquitto（含 WS 监听 8083）
步骤 2node sensor.js 发布温度
步骤 3浏览器打开仪表盘 HTML，数字每秒跳动

还可以用命令行验证：mosquitto_sub -t 'sensor/#' -v 应能看到数据流。三个消费者（命令行、页面、其他订阅者）同时收——一对一 vs 一对多的区别亲身可见。

5. 进阶方向（毕业后的路）

  • 把数据落库：订阅端写个 Node/PHP 服务，入库时序数据库（InfluxDB）
  • 加历史曲线：前端接图表库（ECharts）画折线
  • 上公网：安全三件套（认证+TLS+ACL）+ 云 Broker（EMQX Cloud / 阿里云 IoT）
你已掌握的能力：① 说清 MQTT 为什么适合 IoT；② 理解发布订阅与 Broker；③ 设计 Topic 与通配符；④ 选对 QoS；⑤ 用保留/遗嘱解决状态与掉线；⑥ 理解会话与心跳；⑦ 读懂报文；⑧ 搭建 Broker；⑨ 写 JS/PHP 客户端；⑩ 安全加固；⑪ 端到端串成系统。
