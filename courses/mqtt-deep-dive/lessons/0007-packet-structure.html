课程 0007 · 报文结构：MQTT 在线上到底传什么

MQTT 深入 · 第 7 课 · 预计 15 分钟

前几课都是「概念」，这一课看协议层：MQTT 报文长什么样、为什么能这么省流量、控制报文有哪几种。学完你能读懂抓包、理解「2 字节开销」从哪来。

本节目标：能说出 MQTT 报文的通用三部分结构，能认出常见控制报文的用途。

1. 报文通用结构（三部分）

固定头1-5 字节：报文类型 + 标志 + 剩余长度（可变长编码）
可变头按报文类型不同：Topic、Packet ID、属性等（部分报文没有）
有效载荷消息内容（Payload）；CONNECT 里是 Client ID/用户名密码

最小报文（PINGREQ/PINGRESP）只有2 字节固定头——这就是「轻量」的由来。

2. 控制报文类型（14 种）

连接CONNECT / CONNACK（建连握手）
发布PUBLISH / PUBACK / PUBREC / PUBREL / PUBCOMP（消息与 QoS 确认）
订阅SUBSCRIBE / SUBACK / UNSUBSCRIBE / UNSUBACK（订阅管理）
保活与断开PINGREQ / PINGRESP（心跳）、DISCONNECT（正常断开）

MQTT 5.0 还加了 AUTH（增强认证）等。记住这 14 种就够日常用。

3. 抓一个 PUBLISH 报文看结构

# 发布到 topic "a/b"，内容 "hi"，QoS 1（用 Wireshark 或 mosquitto_sub -v 观察）
固定头: 0x32 [PUBLISH, QoS=1]
剩余长度: 7
可变头: 00 01 61 2F 62   # Topic 长度(2B) + "a/b"
        00 01            # Packet ID = 1
载荷:   68 69            # "hi"

注意 Topic 前要带 2 字节长度前缀，这是 MQTT 的标准编码。

4. 为什么省流量

HTTP每个请求几百字节头（方法、头字段、cookie…）重
MQTT固定头最小 2 字节，无多余头字段省，弱网/低功耗设备友好
关键认知：MQTT 的「轻」是设计出来的：固定头极小、无 HTTP 那种冗长头字段、用二进制长度前缀而非文本换行解析。省流量 = 省电 = 电池设备能用一年。
