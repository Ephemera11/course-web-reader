课程 0001 · MQTT 是什么：物联网为什么换掉 HTTP

MQTT 深入 · 第 1 课 · 预计 12 分钟

你熟悉 HTTP——请求/响应，客户端发起，服务器回答。但物联网设备不是这样说话的：传感器要持续上报，手机要随时收推送，网关可能在弱网下工作。MQTT（Message Queuing Telemetry Transport，消息队列遥测传输）就是为这种场景设计的轻量协议。这一课建立心智模型：MQTT 和 HTTP 到底差在哪，为什么 IoT 选它。

本节目标：能用一句话说清 MQTT 是什么，能说出它和 HTTP 在「通信模型、开销、场景」上的本质区别。

1. MQTT 一句话定义

MQTT 是一种基于「发布/订阅」（Pub/Sub）模型的轻量消息协议。发送方（发布者）不直接发给接收方（订阅者），而是发给一个中间人叫 Broker（代理）；订阅者向 Broker 订阅感兴趣的主题，Broker 负责转发。发送方和接收方互不认识。

2. 和 HTTP 的本质区别

通信模型HTTP：请求/响应（一问一答，客户端发起）MQTT：发布/订阅（推模式，随时双向）
开销HTTP：报文头大（几百字节起步）MQTT：报头最小仅 2 字节
连接方式HTTP：短连接为主（或轮询）MQTT：长连接（TCP 保持，实时推送）
弱网表现HTTP：断线重连麻烦，无 QoS 概念MQTT：心跳 + QoS + 遗嘱，为弱网设计

3. 为什么 IoT 需要它

想象 1000 个温度传感器每秒上报数据，同时 10 个 App 要实时看：用 HTTP，要么 App 疯狂轮询服务器（浪费），要么每个传感器直连 App（不可能）。用 MQTT：传感器只连一个 Broker 发布，App 订阅同一个主题，Broker 一秒转发给所有订阅者——一对多、松耦合、实时。

4. 谁在用 MQTT

  • 智能家居：小米/Home Assistant 设备控制、状态上报
  • 车联网：车辆状态遥测、远程控制
  • 工业 IoT：传感器采集、设备监控
  • 移动推送：很多 App 推送服务底层用 MQTT
  • 消息中转：服务端之间的解耦通信

你熟悉的 PHP 后端也能当发布者/订阅者——MQTT 客户端库在几乎所有语言里都有。
