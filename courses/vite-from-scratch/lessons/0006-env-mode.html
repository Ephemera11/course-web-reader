课程 0006 · 环境变量与 mode 区分开发/生产

Vite 从零入门 · 第 6 课 · 预计 13 分钟

真实项目里，开发环境和生产环境的配置常常不同：API 地址、密钥、开关。Vite 用「环境变量 + mode」优雅解决。这一课你学会用 import.meta.env 读变量、用 .env 文件管理配置、区分 dev / prod。

本节目标：能建 .env 文件、在代码里用 import.meta.env.VITE_XXX 读变量、理解 import.meta.env.MODE 的取值逻辑。

1. 在代码里读环境变量

Vite 把所有环境变量挂到 import.meta.env 上。注意：只有 VITE_ 前缀的变量才会暴露给客户端代码（防止把密钥泄露到浏览器）。

// 代码里
const apiBase = import.meta.env.VITE_API_BASE;
console.log(apiBase); // 例如 https://api.example.com

2. 用 .env 文件管理

项目根目录建 .env（全环境共享）或带后缀的细分文件：

.env所有环境都加载
.env.development只有 npm run dev 时加载
.env.production只有 npm run build 时加载
# .env.development
VITE_API_BASE=http://localhost:3000/api

# .env.production
VITE_API_BASE=https://api.example.com
为什么分文件？dev 时连本地后端、prod 时连线上后端，切换由 Vite 自动按 mode 选文件，你代码里只写 import.meta.env.VITE_API_BASE 一处，无需手动改。

3. mode 是什么

import.meta.env.MODE 在 dev 时是 development，build 时是 production。你也可以在配置里据此分支：

export default defineConfig(({ mode }) => ({
  server: { port: mode === 'development' ? 5173 : 8080 },
}));

4. 安全红线

可以暴露VITE_API_BASE、VITE_APP_NAME 等前端要用的加 VITE_ 前缀，会被打进客户端包
绝不能暴露数据库密码、私钥、secret不加前缀，只存在服务端；或放后端环境变量
