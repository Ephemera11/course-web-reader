课程 0009 · 构建优化：让产物更小更快

Vite 从零入门 · 第 9 课 · 预计 13 分钟

Vite 的默认打包已经不错，但真实上线前常要再挤一挤：拆分包、压缩、按需加载。这一课讲三个最常用、收益最高的优化手段，理解「为什么」比背配置更重要。

本节目标：理解代码分割（code splitting）、依赖预构建、以及 manualChunks 手动分包的作用与配置。

1. 代码分割（动态 import）

写 import()（动态导入）而不是顶层 import，Vite 会自动把那部分代码拆成单独的文件，用到时才加载：

// 点击时才加载 heavy.js，首屏不下载它
btn.onclick = async () => {
  const { doSomething } = await import('./heavy.js');
  doSomething();
};

这叫「按需加载」或「懒加载」，能显著减小首屏体积。

2. 依赖预构建（optimizeDeps）

第 1 课提过，Vite 开发时用 esbuild 预构建 node_modules 的依赖。你可以控制它：

export default defineConfig({
  optimizeDeps: {
    include: ['lodash-es'],   // 强制预构建
    exclude: ['my-local-pkg'], // 跳过预构建
  },
});
为什么要管它？某些包用了特殊语法，esbuild 预构建会报错；或者你想让某个本地包走原生 ESM 不预构建。绝大多数情况不用动，出问题再调。

3. 手动分包（manualChunks）

把不常变的第三方库（vue、react）单独打包，利用浏览器缓存——用户二次访问只下载你改动的代码：

export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          vendor: ['vue', 'axios'],
        },
      },
    },
  },
});

4. 优化手段一览

动态 import首屏必须全量加载按需拆包，首屏更小
manualChunks所有代码混在一个包vendor 独立，长缓存复用
压缩生产默认不压缩Vite 默认用 esbuild 压缩，无需配置
