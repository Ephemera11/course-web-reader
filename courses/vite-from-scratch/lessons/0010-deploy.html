课程 0010 · 部署：把 dist 送到各种平台

Vite 从零入门 · 第 10 课 · 预计 13 分钟

Vite 的产物是纯静态文件（dist/ 目录）。这意味着它能丢到任何能托管静态文件的地方。这一课对比几种主流部署方式，你按自己情况选。

本节目标：知道 Vite 产物是静态文件、能用任意静态托管部署；理解 Vite 官方部署插件、以及 SPA 路由需要 fallback 这个坑。

1. 核心认知：产物是静态的

npm run build 后得到的 dist/，里面全是 HTML/JS/CSS/图片。它不需要 Node 运行时，随便一个静态服务器就能托管——Nginx、Apache、对象存储（OSS/COS）、CDN、Vercel/Netlify 都行。

2. 几种部署方式对比

Vercel/Netlify要配构建命令和输出目录最省心，连 Git 自动部署；build 命令 npm run build，输出 dist
对象存储+OSS手动传文件把 dist 内容上传到 bucket，配静态网站托管 + CDN
Nginx要写配置root 指向 dist；SPA 需加 try_files 兜底到 index.html
GitHub Pages免费但仅静态用 actions 构建后推到 gh-pages 分支

3. SPA 路由的 fallback 坑

如果你用了前端路由（如访问 /about 这个前端路由），用户直接刷新 /about 时，服务器会去找 about.html——找不到就 404。解决：所有未知路径都返回 index.html，让前端路由接管。

# Nginx 做法
location / {
  try_files $uri $uri/ /index.html;
}
Vercel/Netlify 会自动处理这个 fallback（它们识别 SPA）。自己搭 Nginx 才需要手动加。本课你用的阅读器是纯多页（每课一个 HTML），不算 SPA，所以没这坑——但以后做单页应用会碰到。

4. 用官方插件部署（可选）

Vercel/Netlify 都有 Vite 部署插件，能自动处理上述细节。但对纯静态站，直接传 dist/ 也完全够用。
