课程 0001 · Vite 是什么，又解决了什么痛点

Vite 从零入门 · 第 1 课 · 预计 12 分钟

如果你写过前端，大概率被"构建工具"折磨过：装一堆依赖、等几十秒冷启动、改一行代码刷新整页重编译。Vite（法语"快"，读作 /vit/）就是来终结这种痛苦的——它让开发服务器秒开、改代码即时生效。这节课先建立心智模型，下一课就动手跑起来。

本节目标：能说清 Vite 是什么、它靠什么变快、以及它和 webpack 这类老工具的本质区别。先理解"为什么"，再学"怎么用"。

1. Vite 一句话定义

Vite 是一个"前端构建工具 + 开发服务器"二合一的工具。它干两件事：

开发时提供极速开发服务器（dev server），带热更新 HMR——你改代码，浏览器几乎瞬间反映变化，不用整页刷新。
打包时用 Rollup 把你的源码打包成优化过的静态文件，丢到任何静态服务器就能跑（Nginx、Vercel、OSS 都行）。

2. 它凭什么快？两个关键设计

原生 ESM开发时不打包。浏览器原生支持 ES Module（import/export），Vite 直接把源文件按模块发给浏览器，按需加载。没有"先把整个项目打包一遍"这一步，所以冷启动是毫秒级。
esbuild依赖预构建用 Go 写的 esbuild，比 JS 写的打包器快 10-100 倍。只处理第三方依赖（node_modules），业务代码交给浏览器原生跑。

3. 和传统工具（如 webpack）对比

启动速度webpack：先递归打包全部依赖，项目越大越慢（常 10s+）Vite：不打包，按需编译，毫秒级启动
改代码后webpack：重新构建受影响模块，常需秒级等待Vite：HMR 只替换改动的那个模块，即时生效
配置复杂度webpack：loader/plugin 配置繁琐Vite：开箱即用，零配置就能跑
生产打包webpack：自己打包Vite：用 Rollup 打包（更优的产物优化）
关键认知：Vite 在开发时用原生 ESM 跳过打包，在生产时用 Rollup 认真打包。两套策略分工——开发要快，生产要小要稳。这不是偷懒，是"不同场景用不同最优解"。

4. 你会在哪用到它

  • 纯前端项目（HTML/CSS/JS，或配合 Vue/React）
  • 库/组件库开发（Vite 打包出 ESM + UMD 多种格式）
  • 接后端 API 的前端 SPA（单页应用）
  • 甚至能当静态站点生成器（配合插件）

你熟悉的 PHP 后端完全不受影响——Vite 只负责"前端产物"，产物就是一堆 HTML/JS/CSS，丢到 nginx 或 vercel 即可。
