课程 0007 · 多页面（MPA）与库模式

Vite 从零入门 · 第 7 课 · 预计 12 分钟

你以为 Vite 只能做单页应用（SPA）？其实它也能产出多个独立 HTML 页面，甚至能把你的代码打包成一个可发布的 npm 库。这一课讲两种进阶用法：多页面应用（MPA）和库模式（library mode）。

本节目标：理解 MPA 的 build.rollupOptions.input 配置，以及库模式下 lib 字段如何把项目打包成可被别人 import 的库。

1. 多页面应用（MPA）

默认 Vite 只有 index.html 一个入口。想加第二个页面（如 admin.html），在配置里声明多个入口：

export default defineConfig({
  build: {
    rollupOptions: {
      input: {
        main: 'index.html',
        admin: 'admin.html',
      },
    },
  },
});

build 后 dist/ 里会有 index.html 和 admin.html 两个页面，各自独立。适合后台管理 + 前台官网这种多页站。

2. 库模式（library mode）

如果你想把自己写的工具函数/组件打包成 npm 包给别人用，用库模式：

export default defineConfig({
  build: {
    lib: {
      entry: 'src/index.js',      // 库的入口
      name: 'MyLib',                // 全局变量名（UMD 用）
      fileName: 'mylib',             // 产物文件名
    },
    rollupOptions: {
      external: ['vue'],            // 不把 vue 打进包，留给使用者装
    },
  },
});
外部化（external）是关键：库不应把 React/Vue 这类「运行时依赖」打进产物，否则使用者会装两份。用 external 把它们排除，在 package.json 的 peerDependencies 里声明即可。

3. 两种模式对比

SPA（默认）一个 index.html，前端路由切换视图最常用，适合 Web 应用
MPA多个独立 HTML 页面适合多页站、后台+前台
库模式产出可被 import 的 npm 包适合造轮子、组件库
