课程 0003 · 理解 index.html 与 ESM 模块图

Vite 从零入门 · 第 3 课 · 预计 14 分钟

第 2 课你跑起了项目，但可能还有疑问：为什么 index.html 必须放根目录？浏览器怎么就能直接跑 import？这一课把模块加载的底层机制讲透，你会真正理解 Vite「不打包」的妙处。

本节目标：能解释 ESM 是什么、浏览器原生怎么加载它、以及 Vite 在开发时如何利用它做到「不打包也跑得起来」。

1. 什么是 ESM

ESM = ECMAScript Modules，是 JavaScript 官方的模块标准。你写的 import / export 就是 ESM 语法。在浏览器里，只要 <script type="module">，浏览器就按模块规范去加载。

// main.js —— 这就是一个 ESM 模块
import { add } from './math.js';   // 浏览器看到这行，会再去请求 math.js
console.log(add(1, 2));

关键：ESM 是「浏览器原生支持」的。现代 Chrome/Firefox/Safari 不需要任何打包器，自己就能解析 import 并去拉取对应文件。

2. Vite 怎么用 ESM「不打包」

传统打包器启动前先把所有 import 递归拼成一个大文件，再交给浏览器。项目越大，拼得越久。
Vite 开发时不拼。浏览器请求 index.html → 发现 main.js → 浏览器自己再去请求 main.js 里 import 的每个文件。Vite 只负责把文件原样发给浏览器 + 处理第三方依赖。
所以 Vite 的快，本质是「把打包的活儿交还给浏览器」。浏览器本来就能按需加载模块，Vite 只是不挡在这中间做全量预构建了。

3. 为什么 index.html 要在根目录

Vite 以 项目根目录 作为「网站根（root）」。index.html 放根目录，浏览器访问 / 就能直接拿到它；它里面写的 src="/main.js" 这个绝对路径，Vite 才能正确解析到根下的 main.js。

如果 index.html 放到 src/ 子目录，路径关系就乱了，需要额外配置 root 或 rollupOptions.input。对初学者，保持默认最省心。

4. 一张模块图

假设项目结构如下，浏览器加载时的请求链条是这样的：

index.html
  └─ <script type=module src=/main.js>
       ├─ import './style.css'   → Vite 把它转成一段 JS 注入样式
       └─ import { add } from './math.js'
            └─ math.js 里又 import 别的… 浏览器逐层去拉

每个 import 都是一次独立的 HTTP 请求（开发时）。你改了 math.js，只有 math.js 这个请求重新来一遍，其他文件纹丝不动——这就是 HMR 能做到「秒级更新」的底层原因。

5. 一个常见误区

误区「不用打包器，浏览器一个个拉文件，请求太多很慢吧？」开发时确实多请求，但本地毫秒级响应；生产时 Vite 用 Rollup 打包成少量文件，没这问题
误区「import 只能在 Node/打包器里用」错。浏览器原生支持 ESM，type=module 即可
误区「CSS 也能 import 很奇怪」Vite 把 import './x.css' 编译成运行时注入 style 标签，是 Vite 的能力
