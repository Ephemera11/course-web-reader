课程 0008 · CSS 预处理器与静态资源处理

Vite 从零入门 · 第 8 课 · 预计 13 分钟

Vite 对样式和静态资源（图片、字体）的处理几乎是「零配置开箱即用」。这一课讲：怎么用 SCSS/Less、CSS 模块化、以及图片字体怎么引入、构建后去哪了。

本节目标：会用 import './x.scss' 直接引入预处理器样式、理解 CSS Modules 的 .module.css 写法、知道图片 import 后得到的是打包后的 URL 字符串。

1. CSS 预处理器（SCSS/Less）

装好对应的编译器，就能直接 import 预处理文件，无需额外配置：

// 安装（以 scss 为例）
// npm i -D sass

// main.js
import './style.scss';  // Vite 自动用 sass 编译
零配置原理：Vite 检测到 .scss 后缀就去找 sass 包编译。装了就有，没装就报错提示你装——不需要写 loader 配置（对比 webpack 的 sass-loader 那一堆）。

2. CSS Modules（局部作用域）

普通 CSS 是全局的，类名容易冲突。把文件命名为 xxx.module.css，Vite 会把它编译成「局部作用域」：

/* style.module.css */
.title { color: #7c2d12; }

// main.js
import styles from './style.module.css';
el.className = styles.title;  // 实际拿到一个唯一哈希类名

3. 静态资源（图片/字体）

在 JS 或 CSS 里 import 一张图，得到的是它构建后的最终 URL：

import logoUrl from './logo.png';
// logoUrl 形如 '/assets/logo-abc123.png'
img.src = logoUrl;

构建时 Vite 会把图片复制到 dist/assets/ 并加哈希防缓存。小于阈值的图（默认 4KB）会被转成 base64 内联，减少请求。

4. 资源处理对比

URL 引用CSS 里 url('./a.png')Vite 自动解析、打包、加哈希
import 引用JS 里 import x from './a.png'拿到最终 URL 字符串
public 目录放 public/favicon.ico原样拷贝到 dist 根，路径用 /favicon.ico
