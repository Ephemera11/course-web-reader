课程 0004 · vite.config.js 与路径别名 @

Vite 从零入门 · 第 4 课 · 预计 13 分钟

前 3 课我们零配置跑起来了项目。但真实项目需要配置：端口、别名、插件。这一课讲 Vite 唯一的配置文件 vite.config.js，重点搞定最常用的「路径别名 @ → src」。配好之后，你就能写 import x from '@/utils' 而不用写一长串 ../../。

本节目标：能写出一个最小 vite.config.js，配好 @ 别名，并理解它为什么能让你少写 ../。

1. 配置文件长什么样

项目根目录新建 vite.config.js，默认导出配置对象：

// vite.config.js
import { defineConfig } from 'vite';

export default defineConfig({
  // 这里是配置项
});

defineConfig 不是必须的，但它提供 TypeScript 类型提示，强烈建议用。

2. 路径别名 @

没有别名时，深层文件要写 import api from '../../../utils/api'，又丑又易错。配了 @ 指向 src 后，全项目统一写 import api from '@/utils/api'。

import { defineConfig } from 'vite';
import { fileURLToPath, URL } from 'node:url';

export default defineConfig({
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
});
要点：别名值必须是一个绝对路径。fileURLToPath(new URL('./src', import.meta.url)) 是在 ESM 环境里把 ./src 转成绝对路径的标准写法——比写 __dirname 更现代。

3. 顺手配几个常用项

server.port改开发服务器端口，如 5174，避免和别的项目冲突
server.opentrue 启动后自动打开浏览器
base部署到子路径时设，如 /my-app/；根域名部署留空
export default defineConfig({
  base: '/',
  server: { port: 5174, open: true },
  resolve: { alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) } },
});

4. 改完配置要重启

vite.config.js 的改动不会热更新——必须停掉 npm run dev 重新启动才生效。这是新手常踩的小坑。

小测
