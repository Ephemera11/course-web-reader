课程 0002 · 装：用 npm，不是 clone

TencentDB Agent Memory 入门 · 第 2 课 · 预计 12 分钟

这一课只有一个动作：把包装下来。但装之前的三条检查和装之后的一次确认，决定了你后面半小时是在调试还是在干活。

本节目标：在自己机器上装好 1.0.x 版本，并能说出包里有哪几个目录、哪个是你真正要用的。

1. 前置闸：三条命令

node -v        # 要求 >= 22.16.0（package.json 的 engines 字段）
npm -v
npm view @tencentdb-agent-memory/memory-tencentdb version

第三条命令一箭三雕：证明包存在、证明你的 registry 可达、告诉你当前真实版本号。

为什么这三条不能跳：node 低于 22.16 时依赖照样能装上，但运行时才炸——涉及 sqlite-vec 原生模块与 @node-rs/jieba 中文分词。报错点离根因很远，你会以为是代码有 bug。

2. 装包

mkdir -p /c/tdai && cd /c/tdai
npm init -y
npm install @tencentdb-agent-memory/memory-tencentdb

实测：包体约 1MB，依赖 24 个，其中值得注意的是这三个——sqlite-vec（向量存储）、@node-rs/jieba（中文分词）、tsx（TypeScript 运行时，gateway 只有 .ts 源码没有编译产物，靠它直接跑）。

3. 装完之后包里有什么

不要只看 node_modules 有没有生成。解包看一眼结构，你会少走很多弯路：

node_modules/@tencentdb-agent-memory/memory-tencentdb/
├── dist/           编译好的插件入口（只有 6 个 .mjs，不含 gateway）
├── src/            全部源码，gateway 在这里：src/gateway/server.ts
├── bin/            三个 CLI：迁移、导出、读本地记忆
├── hermes-plugin/  ★ 你要用的 Hermes provider（v1 与 v2 各一个）
├── openclaw-plugin/OpenClaw 侧的插件包
└── scripts/        安装脚本（v1 的 .sh/.bat、v2 的 .sh）
关键认知：npm 包没有预编译 gateway（dist/ 里只有插件入口，没有 server 构建产物）。所以起 gateway 必须用 tsx 现场转译 src/gateway/server.ts——这也解释了下一课要讲的那个坑。

4. 忽略那条 postinstall

安装时你会看到它跑了一段 shell：

bash scripts/openclaw-after-tool-call-messages.patch.sh 2>/dev/null || true

这是给 OpenClaw 打补丁用的，末尾的 || true 保证它失败也不中断安装。没有 OpenClaw 的机器上它是空操作，不需要处理。

5. 确认装的是哪个版本

node -p "require('./node_modules/@tencentdb-agent-memory/memory-tencentdb/package.json').version"
# 实测输出：1.0.3

为什么要单独确认？因为 main 分支的源码里写的是 0.3.6，而 npm 上是 1.0.x。如果你一边看 GitHub 上的源码一边装 npm 包，两边对不上时会怀疑人生——先确认自己手上是哪个版本。

6. 装完先别急着配 Hermes

顺序很关键。先把 gateway 单独跑起来、验证它能记事，再去改 Hermes 配置。反过来的话，一旦 Hermes 没反应，你分不清是 provider 没加载还是 gateway 没起来——两个变量同时动，调试成本翻倍。

下一步预告：0003 会单独起一个 gateway，不碰你现有 Hermes 的任何配置。等 0004 用四道门证明它真的在记东西，0007 才动配置文件。
