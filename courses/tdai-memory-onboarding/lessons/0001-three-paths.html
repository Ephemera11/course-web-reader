课程 0001 · 先判定形态：一个仓库里装了两套产品

TencentDB Agent Memory 入门 · 第 1 课 · 预计 12 分钟

学这门课最省时间的一步，不是记住命令，而是在输入第一条命令之前判断自己走的是哪条路。因为 TencentCloud/TencentDB-Agent-Memory 这一个仓库里，装了两套内核完全不同、命令完全不通用的产品。

本节目标：看到任何一篇 TDAI 教程，30 秒内判断它讲的是哪条路；并知道自己这台机器只能走哪条。

1. 两条代码树

项目把「团队版服务端」放在默认分支，把「本地插件版」放在 main。你用 git clone 不加分支参数时，拿到的是默认分支。

默认分支 feat/server_team分支 main
是什么团队版服务端：MemoryCore / MemoryProxy / MemoryPanel / MemoryKnowledge + deploy本地插件版：openclaw 插件 + hermes provider
体量约 1259 个文件约 173 个文件
根目录有 package.json没有（请求返回 404）有
装法Docker 起三个镜像npm 装包
默认端口8420 / 8125 / 8424 / 8096gateway 8420

自己验证这件事只需要两条命令（不需要 clone 整个仓库）：

# 默认分支根目录没有 package.json
curl -s -o /dev/null -w "%{http_code}\n" \
  https://raw.githubusercontent.com/TencentCloud/TencentDB-Agent-Memory/feat/server_team/package.json
# → 404

# main 分支有
curl -s -o /dev/null -w "%{http_code}\n" \
  https://raw.githubusercontent.com/TencentCloud/TencentDB-Agent-Memory/main/package.json
# → 200
第一个必踩的坑：网上大量教程写「clone 仓库，然后 npm install」。你照做会失败——因为 clone 下来的是默认分支，那里根本没有 package.json。想装本地插件要直接用 npm 装包，不要 clone。

2. 四套版本号，没有一套能对上

这是最迷惑人的地方。同一个项目，四个地方报四个不同的版本：

你看到的它是什么
1.0.3npm 上真正能装的那个包（2026-10 实测）
0.3.6main 分支 package.json 里写的（落后于已发布版本）
v2.0.3-beta.1GitHub Release，对应服务端团队版
0.1.0gateway 运行时在 /health 里自报的内部版本
记住一句话就够：要装包就认 npm registry 的版本，要看服务端功能就认 GitHub Release，别拿 Release 号去 npm 找包，也别拿 npm 版本号去对 Docker 镜像 tag。

4. 你这台机器只能走哪条

选路不是看兴趣，是看网络和已装软件。实测结论：

检查项结果影响
openclaw --version未安装路 C 不可跑
docker manifest inspect 镜像registry-1.docker.io 超时；registry mirror 列表为空路 B 需先配镜像加速
npm view 包版本1.0.3（走国内镜像，可达）路 A 可用
本课程的主线因此固定为路 A。路 B 会讲清判定依据与文档索引，但不会假装跑过——这一点在最后一课会再强调一次，因为「没跑过却写成跑过」是技术资料最常见的失真方式。

5. 还有一个隐藏的第四条路

解包 npm 包后会看到两个 provider 目录，很多人只看到第一个：

hermes-plugin/memory/memory_tencentdb/      ← v1：自己拉起本地 gateway，L0~L3 存本机
hermes-plugin/memory/memory_tencentdb_v2/   ← v2：连一个已经跑着的 gateway（远端/容器）

v1 适合单机自用；v2 适合你已经把团队版三件套跑起来之后，让 Hermes 去连它。本课程主线走 v1，最后一课会提到 v2 的接入差异。
