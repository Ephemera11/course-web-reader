课程 0006 · 检索原理：关键词能搜到什么，搜不到什么

TencentDB Agent Memory 入门 · 第 6 课 · 预计 12 分钟

你可能已经注意到 /health 里 embeddingService 是 false，而搜索结果里还是写着 strategy: fts。这一课讲清这两个词意味着什么，以及什么情况下你的记忆会「明明在库里却搜不出来」。

本节目标：能解释这次检索走了哪条路径、score 从哪来、什么时候必须补 embedding。

1. 一次检索的真实链路

以下是我实测时从 gateway 日志里摘的原样输出（查询词是「招投标」）：

[tdai_conversation_search] CALLED: query=招投标, limit=5,
  vectorStore=available, embeddingService=UNAVAILABLE
[hybrid-fts] FTS5 query: "投标" OR "招投标"
[hybrid-fts] FTS5 returned 2 candidates
RESULT (strategy=fts): returning 2 messages (scores: [0.709, 0.686])
日志说明
embeddingService=UNAVAILABLE没有向量能力，自动退回关键词检索
FTS5 query: "投标" OR "招投标"jieba 把你的查询词切开了，用 OR 展开成多个检索式
strategy=fts本次走的是 SQLite FTS5 全文索引，不是向量
scores: [0.709, 0.686]BM25 相关性打分，相对值，不是「置信度」

2. jieba 在中间做了什么

中文没有空格，全文检索器不切词就查不了。所以它用 jieba 先切：「招投标」被切成「投标」和「招投标」，然后用 OR 都去查。

好处：你搜「招投标」时，含「投标」的句子也能命中。这也是你实测搜「招投标」能命中「招投标情报系统」那条的原因——这不是语义理解，是分词展开的功劳。
代价：词形不同就搜不到。你说「情报系统」、库里写「情报平台」，两个词没有共同分词结果，就查不出来。这是关键词检索的物理限制，不是参数没调好。

3. 什么时候必须上 embedding

场景纯 FTS 够不够
找自己写过的原话、项目名、函数名、错误码够，而且更快更准
同义改写（「情报平台」vs「情报系统」）不够
跨语言（中文问、英文记）不够
模糊意图（「上次说的那个备份规矩」）不够

要开向量检索，配这四个字段（少任何一个都会降级）：

{"embedding":{
  "enabled": true,
  "provider": "openai",
  "baseUrl": "https://api.openai.com/v1",
  "apiKey": "${EMBEDDING_API_KEY}",
  "model": "text-embedding-3-small",
  "dimensions": 1536
}}
静默降级的陷阱：apiKey / baseUrl / model / dimensions 少任何一个，系统会继续运行但自动退回非向量模式——不报错、不提示。你会觉得「我明明配了 embedding，怎么还是搜不到同义词」。判断依据只有一个：/health 里 embeddingService 是否变成 true。

4. 一个容易误解的数字

score: 0.686 这种值不要当阈值用。它来自 BM25：词在多少文档里出现、出现几次、文档多长——全部是相对当前库算出来的。库里只有 10 条时的高分，和库里 10 万条时的高分不是同一个尺度。

实践建议：用 score 排序看相对高低可以，用它卡绝对阈值（比如「低于 0.5 就不注入」）会随数据量漂移。真要卡阈值，先在自己库里采样看分布。
