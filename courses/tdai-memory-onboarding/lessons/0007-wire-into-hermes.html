课程 0007 · 接进 Hermes：改哪一行，怎么证明它认了

TencentDB Agent Memory 入门 · 第 7 课（收尾）· 预计 15 分钟

到这一课 gateway 已经能独立记事。剩下的事只有一件：让 Hermes 用它。这一步最容易的失败不是报错，而是「文件放对了、配置写了，但 Hermes 根本没扫到那个目录」——所以验收必须用官方的发现函数，不是 ls。

本节目标：完成接线三步，并用一个函数输出 True/False 证明 Hermes 真的加载了 provider。

1. 先确认你的 HERMES_HOME 在哪

echo "$HERMES_HOME"

这一台机器上它的值是 C:\Users\WTY\AppData\Local\hermes，而不是文档里常写的 ~/.hermes（那个目录在本机根本不存在）。这不是小差别：provider 放在错的目录里，Hermes 永远不会加载它。

规则：所有「放到 ~/.hermes/...」的指示，都要先翻译成 $HERMES_HOME/...。文档里的路径是按默认安装假设写的。

2. 接线三步

# ① 复制 provider（目录名必须是 memory_tencentdb，下划线）
cp -r node_modules/@tencentdb-agent-memory/memory-tencentdb/hermes-plugin/memory/memory_tencentdb \
      "$HERMES_HOME/plugins/memory_tencentdb"

# ② 在 $HERMES_HOME/config.yaml 的 memory: 段下加一行
#    memory:
#      provider: memory_tencentdb

# ③ 验证 Hermes 能发现它
cd "$HERMES_HOME/hermes-agent" && venv/Scripts/python.exe -c "
from plugins.memory import discover_memory_providers
for name, desc, avail in discover_memory_providers(): print(name, avail)"
目录名是最容易错的一处：plugin.yaml 里 name: memory_tencentdb（下划线），而 pmemory-tencentdb（连字符）只是 config 里的别名。目录名必须等于 plugin.yaml 的 name，写成连字符会静默不加载。

3. 装之前的基线（我在这台机器上实测的）

byterover  False
retaindb   False
hindsight  True      ← 当前生效的 provider

装完再跑同一条命令，列表里应该多出 memory_tencentdb True。这个 True 就是本节唯一有效的验收标准——`ls` 看到文件不算，看到目录也不算。

4. 两个安装脚本并不等价

脚本怎么定位 HERMES_HOME在本机的后果
setup-hermes-memory-tencentdb.bat（第 40 行）if "%HERMES_HOME%"=="" set "HERMES_HOME=%USERPROFILE%\.hermes" — 尊重已有变量装到正确位置
install_hermes_memory_tencentdb.sh（第 53 行）HERMES_HOME="$USER_HOME/.hermes" — 硬编码装到 Hermes 根本不看的目录
Windows 上就用 .bat。另外它有个前提：脚本发现 config.yaml 已存在时只会打印要加的 YAML，不会替你改——所以第 ② 步要你手工粘贴。

5. 第四条路：v2 provider

npm 包里还有一个 memory_tencentdb_v2，它不自己起 gateway，而是用 Python SDK 连一个已经跑着的 gateway（比如 Docker 三件套起来之后）。

PYTHON_BIN="$HERMES_HOME/hermes-agent/venv/Scripts/python.exe" \
  bash scripts/install-hermes-plugin-v2.sh
Windows 专属坑：v2 脚本按 POSIX 惯例找 venv/bin/python，而 Windows 的 venv 是 venv/Scripts/python.exe。不显式传 PYTHON_BIN 会报「Hermes Python not found」。它的 SDK wheel 也不在 PyPI，走 cmb 直链下载。

6. 十六个坑，一页看完

#坑解药
1默认分支没有 package.json插件用 npm 装，不要 clone
2promptMode 文档冲突以 .env.example 为准（默认 code）
3端口 8420 双占Docker 与 provider 默认同端口，改一个
4四个 header 缺一即 bypassteam/agent/task/conversation-id 要齐
5搜索工具凭空消失设 GATEWAY_CMD 或 PORT 让工具乐观注册
6配置被脚本覆写PROXY_CONFIG_DIR 指自己的目录
7user/create 不入队再调 team-member/add
8admin 与业务用户混用admin 只做组织管理
9.bat 与 .sh 不等价Windows 用 .bat
10node --import tsx 崩用 tsx/dist/cli.mjs
11MSYS 路径被误解析传 C:/... 原生路径
12残留进程污染验收tsx 有三层进程链，按 PID 逐个清
13运行中读库读到 0 行停进程后读，或只信 API
14tasksCompleted 是弱判据认 /search/memories 有结果
15包里还有 v2 provider单机 v1，接远端 v2
16v2 脚本找不到 Windows python显式设 PYTHON_BIN

7. 什么还没被验证（诚实清单）

项目为什么没验
Docker 三件套端到端该网络下 registry 超时，镜像拉不下来
L1/L2/L3 真的抽出记忆没有用你的密钥做实验；只验证了「没 key 时恒空」这一侧
Hermes 真正加载 provider需要改 config.yaml 并写 plugins 目录，属于改你环境，要你同意
v2 provider 端到端需要先有跑着的 gateway + 装 Python SDK
把这四条写下来，比多跑通一条路径更有价值。技术资料最常见的失真，就是把「应该能」写成「已经能」。
