课程 0003 · 起 gateway：三种起法与三个坑

TencentDB Agent Memory 入门 · 第 3 课 · 预计 15 分钟

gateway 是这套东西的心脏：它同时是 HTTP 服务、记忆存储和流水线调度器。它起不来，后面全免谈。这一课的三个坑我都在真机上踩过，其中两个是官方文档给的第一种起法在这台机器上直接失败。

本节目标：用正确的方式起一个 gateway，能分辨哪些启动日志是正常噪声、哪些是真故障。

1. 三个环境变量决定一切

变量默认出处
TDAI_GATEWAY_PORT8420src/gateway/config.ts:377
TDAI_DATA_DIR用户目录下的 .memory-tencentdb/memory-tdaigateway 侧解析
TDAI_LLM_API_KEY / _BASE_URL / _MODEL空 / openai / gpt-4osrc/gateway/config.ts:397

没有 LLM key 也能把 gateway 起起来、能写能读 L0——只是抽不出 L1 记忆（0005 会讲清这件事）。这一点很重要：起服务与抽记忆是两件事。

2. 三种起法

方式谁拉起 gateway适用
自动发现Hermes provider 自己找 src/gateway/server.ts 并 Popen装进 Hermes 后的默认行为
显式指定provider 按 MEMORY_TENCENTDB_GATEWAY_CMD 拉起gateway 不在标准路径时
自己起（本课用）你手动跑，provider 只检测 /health先独立验证，不碰 Hermes 配置

本课走第三种：单独起、单独验，跟你的 Hermes 完全隔离。

3. 坑一：官方文档的第一种起法在这台机器上崩

provider 文档里写的是 node --import tsx src/gateway/server.ts。实测在 node v24 上直接崩：

$ node --import tsx src/gateway/server.ts
Error: The service was stopped
    at .../node_modules/esbuild/lib/main.js:1001:38
    at .../node_modules/esbuild/lib/main.js:886:9
  name: 'TransformError'

换 tsx 自己的 CLI 就正常：

# 在包目录里
export TDAI_DATA_DIR="C:/tdai/memory-data"
export TDAI_GATEWAY_PORT=8420
node ./node_modules/tsx/dist/cli.mjs src/gateway/server.ts

4. 坑二：路径写对了，文件却跑到别的盘

git-bash 里 $TMPDIR 常是 /tmp。你把它传给 node，node 会把它当成当前盘根目录下的 \tmp——实测数据跑到了 C:\tmp\...，而不是你以为的用户临时目录。

规则：凡是传给 node / docker 这些原生程序的路径，一律写成 C:/Users/... 这种 Windows 原生形式。$TMPDIR、/tmp 这类 MSYS 路径只在自己 shell 里用。

验证办法：起好后看日志里那行 Initializing TDAI Core: dataDir=...，它写的是程序真实解析出来的路径，不是你以为的路径。

5. 坑三：进程链没关干净，端口被幽灵占着

tsx 起服务是一条三层链：shell → tsx/dist/cli → node。你杀掉其中一层，另外两层可能还活着，继续占着 8420，继续往你已经删掉的目录里写数据。新进程则会报：

Gateway startup failed: Error: listen EADDRINUSE: address already in use 127.0.0.1:8420

排查与清理：

# 谁占着端口
netstat -ano | grep ":8420" | grep LISTENING
# 那个 PID 到底是什么进程
powershell -NoProfile -Command "Get-CimInstance Win32_Process -Filter 'ProcessId=1234' | Select-Object Name,CommandLine"
# 确认是自己的 gateway 再按 PID 杀，别按进程名批量杀 node
为什么这条重要：这是唯一一类会让你「验证了半天，验的是另一个库」的故障。它不报错、不提示，你在 A 端口上看到的每一条记忆都可能来自 B 目录。

6. 启动成功的日志长什么样

INFO  [memory-tdai] [core] StorageAdapter set: type=local
DEBUG [memory-tdai][factory] Store created: backend=sqlite, dbPath=...\vectors.db, dimensions=0, embedding=disabled, bm25=enabled
DEBUG [memory-tdai][sqlite] FTS5 tables initialized (l1_fts, l0_fts) [schema v2 — jieba segmented]
DEBUG [memory-tdai] [pipeline] Initialized: everyNConversations=5, warmup=enabled, l1IdleTimeout=600s
WARN  [memory-tdai][sqlite] nested vec0.so not found under .../sqlite-vec-linux-x64; falling back to sqlite-vec loader
WARN  [gateway] integrations/ not available (...); falling back to inline LocalConfigSource (standalone only)
INFO  [timer-scanner] Started (leaderless mode, all pods scan)
INFO  [gateway] Pipeline Worker started
日志能读出什么正常吗
bm25=enabled、jieba segmented中文关键词检索可用正常
embedding=disabled没配 embedding，只有关键词检索正常（不等于坏）
vec0.so not found 那条 WARN去找 Linux 目录没找到，回退到正常 loader正常噪声
integrations/ not available 那条 WARN私有子模块未开源，standalone 模式回退正常噪声
别被 WARN 吓到：上面两条 WARN 在正常启动里都会出现。唯一可信的判据是下一课的 /health 返回 200。
