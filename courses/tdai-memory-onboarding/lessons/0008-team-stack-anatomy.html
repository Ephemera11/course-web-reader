课程 0008 · 三件套解剖：core / hub / proxy 各管什么

TencentDB Agent Memory 入门 · 第 8 课 · 预计 14 分钟

前七课我们用本地插件把记忆跑通了。这一课转向另一条形态——团队版三件套。虽然我这台机器拉不到镜像（registry 超时），但它的架构决定了你以后会遇到的所有配置项，而且第 9 课要讲的注入链路就藏在这里。

先声明边界：本课内容是文档与脚本层面的解剖，不是我在你机器上跑通过的结果。Docker Hub 在这台机器 15 秒超时、没有 registry mirror，所以三个镜像我一个都没拉下来。
本节目标：说清三个容器各自的职责与端口，理解为什么它要两组独立的 LLM 配置。

1. 三个容器

组件容器名端口管什么
memory-coretdai-memory-core8420内核 gateway：记忆读写、鉴权、skill/RAG 数据面
memory-hubtdai-memory-hub8125 / 8424管理面板 Panel + 知识服务 Knowledge（合并镜像）
proxytdai-proxy8096LLM 请求转发代理，coding agent 的 API 入口

注意 memory-hub 是一个镜像占两个端口：8125 是给人看的 Web 面板，8424 是给程序用的 Knowledge API（有 Swagger 在 /docs）。

2. 数据流

编码 Agent（Claude Code / CodeBuddy / ...） │ OpenAI 或 Anthropic 协议（一行代码都不改） ▼ memory-proxy :8096 ← 只做转发与注入，自己不存记忆 ├──────────────► 上游 LLM └─ HTTP ───────► memory-core :8420 ├─ Memory L0 / L1 / L2 / L3 ├─ Skill 检索 / 归档 / 抽取 └─ Meta Team / Agent / Task / Knowledge memory-hub :8125 面板 :8424 知识服务（Wiki / CodeGraph）
一句话分工：proxy 管「接入与转发」，core 管「记忆的存储与处理」，hub 管「人看的界面 + 文档/代码知识」。proxy 自身不落任何记忆数据——这一点决定了排障时该去哪个容器看日志。

3. 为什么两组 LLM 是独立配置

.env.example 把 LLM 分成两组，这不是冗余，是两个完全不同的用途：

组谁在用干什么
MEMORY_LLM_*memory-core + memory-hub记忆的 embed / summarize、wiki ingest 的摘要
PROXY_UPSTREAM_*proxy你 agent 的实际请求转发目标
实践含义：记忆侧的抽取可以用便宜的小模型（只要结构化输出稳定），而编码 agent 走贵的大模型。两组可指向不同供应商、不同模型，start-all.sh 甚至会问「proxy 组是否复用 memory 组」来省一次填写。

4. verify.sh 的预检机制（很聪明，值得学）

启动前它会真的打一次 LLM 端点，但尽量不花钱：

协议怎么验成本
OpenAI 兼容GET {base}/models零 token，只验 key 与 URL
AnthropicPOST {base}/v1/messages 发 max_tokens=1 的最小消息≤ 10 token

更细的一点：容器已在运行时，它还会从容器内部 exec 一次 curl。因为有些企业代理 / DNS 隔离环境里"宿主机能连、容器连不上"——这个差异只有从容器里发请求才暴露得出来。

失败长这样（文档原例）：

[error] memory 组 API key 无效（HTTP 401）：https://api.deepseek.com/v1/models
{"error":{"message":"Authentication Fails, Your api key: ****abcd is invalid",...}}
为什么这点值得学：它把「key 错 / URL 错 / 模型名错」提前到启动前拦下，而不是等到 wiki ingest 或第一次对话时才 401。这是很值得抄的工程习惯——错误越早暴露，排查成本越低。

5. 启动顺序与预检

start-all.sh 干的事按顺序是：

① .env 不存在 → 从 .env.example 复制
② 交互式填两组 LLM（回车保留默认）
③ 立即检查 LLM 通路，不通就重填
④ 写回 .env 持久化
⑤ 校验全部必填参数（避免起了一半才发现 proxy 参数缺）
⑥ 端口预检（一次性查 4 个端口是否被占用）
⑦ memory → 等 healthy → memory-hub → 等 healthy → proxy
⑧ 打印 Claude Code 的一行接入命令
第 ⑥ 步很关键：端口预检放在启动之前，而且要排除自己旧容器。这就是为什么它能避免「起了一半发现 8096 被别的项目占了」这种尴尬。

只想检查不想启动：

./verify.sh              # 全检（含 LLM 通路）
./verify.sh --skip-llm   # 离线环境跳过 LLM 检查

6. 停止与清理

./stop-all.sh            # 停容器，保留 volume 数据与 admin key
./stop-all.sh --purge    # 连 volume、admin key、proxy config 一起清
注意 --purge：它会连数据卷一起删。如果你的记忆数据没备份，这一步是不可逆的。
