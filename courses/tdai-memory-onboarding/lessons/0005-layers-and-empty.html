课程 0005 · L0 到 L3：为什么什么都没抽出来

TencentDB Agent Memory 入门 · 第 5 课 · 预计 14 分钟

上一课你已经看到：L0 写进去了、能搜回来，但 L1 是空的。「装了但没记忆」是这类项目最常见的抱怨，而它其实只有四种原因——其中两种是配置问题，一种根本不是问题。

本节目标：能按顺序排除四种「抽不出记忆」的原因，并知道 promptMode 该怎么选。

1. 四层各自是什么

L0 Conversation · 原始对话，逐条消息。capture 时立即写入。不需要 LLM。
L1 Atom · 从对话里抽出的事实 / 偏好 / 约束 / 事件，去重后写入。必须调 LLM。
L2 Scenario · 围绕场景聚起来的知识块。L1 攒够后由 LLM 归纳。
L3 Persona · 长期画像。触发阈值到了才更新。

启动日志里那行就是它的调度节奏：

pipeline Initialized: everyNConversations=5, warmup=enabled,
  l1IdleTimeout=600s, l2DelayAfterL1=10s,
  l2MinInterval=900s, l2MaxInterval=3600s, sessionActiveWindow=24h
参数含义
everyNConversations=5每 5 轮对话触发一次 L1
l1IdleTimeout=600s空闲 10 分钟也会兜底触发
l2DelayAfterL1=10sL1 完成后 10 秒排 L2
l2MinInterval=900s / l2MaxInterval=3600sL2 最快 15 分钟、最慢 1 小时一次
时间预期：聊完 5 轮之后 L1 才启动；L2 要再等；L3 最慢。刚聊两句就去看 L2/L3 有没有内容，一定会失望——这不是故障，是分层沉淀的节奏。

2. 四种「抽不出记忆」的原因

#原因症状怎么确认
1没配 LLML0 正常，L1 恒空，/recall 空但 code:0l1_records 为 0 且没设 TDAI_LLM_API_KEY
2promptMode 与内容不匹配配了 key 也不出条，或只出很少看当前模式是 code 还是 chat
3对话里没有可抽的东西纯寒暄、纯工具调用换成有事实/约束/决策的对话再试
4去重把新条目合并掉了重复说同一件事不产生新条enableDedup 开关

3. 那个自相矛盾的 promptMode

同一个仓库里，两处文档说的默认值不一样：

来源说的是
deploy/global-images/.env.example（第 138-143 行）code 是默认；chat 面向个人对话
INSTALL_CN.md 的 FAQ（第 299 行）默认 chat，配成 code 而聊闲天时会抽出 0 条
以配置模板为准：.env.example 就是实际下发的值，它说默认是 code。所以默认情况下你是在用「面向工程协作」的抽取规则处理对话。

两个模式的分工：

模式面向抽什么
code代码工程 / 团队协作项目事实、任务、决策、SOP、禁忌
chat个人对话 / 教学 / 闲聊persona、episodic、instruction 类记忆
实用判断：让 agent 帮你写代码、跑测试、做工程决策 → 保持 code；把 agent 当私人助理聊天、聊偏好和习惯 → 改成 chat。用错模式的症状很隐蔽：不是报错，而是「什么都没发生」。

4. 配了 LLM 之后该看到什么

# 给 gateway 一个 OpenAI 兼容端点
export TDAI_LLM_API_KEY="sk-..."
export TDAI_LLM_BASE_URL="https://api.deepseek.com/v1"
export TDAI_LLM_MODEL="deepseek-chat"

然后按上一课的替代判据验：/search/memories 的 total > 0，或停进程后 l1_records 行数 > 0。

别用 tasksCompleted 判断：它会给你绿灯，即使一条记忆都没抽出来。
