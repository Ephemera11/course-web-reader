课程 0011 · 收官：给你自己配一套 memory loadout

TencentDB Agent Memory 入门 · 第 11 课（收官）· 预计 15 分钟

最后一课不引入新命令，而是把视角从「怎么装」抬到「怎么用」。这套系统的核心主张不是"记住更多"，而是「什么值得留下、谁能用、下一次怎样少拿但拿对」。理解了这一层，你才知道自己该往里放什么。

本节目标：认清四类记忆资产各自解决什么问题，并给自己列出一份可执行的 loadout 清单。

1. 四类资产，别混为一谈

Chat Memory · 偏好、事实、决策、交互历史。解决「换个会话就要重新自我介绍」。
分层：L0 原始对话 → L1 原子事实 → L2 场景块 → L3 画像。
Skill · 跑通过的操作方法。解决「同一个坑踩第二遍」。
关键：它不只是 prompt，还带版本、资源文件、触发边界、执行步骤、验证规则。
LLM-Wiki · 文档变成结构化页面 + 链接图谱。解决「每个 agent 从目录第一页重读」。
设计灵感来自 Karpathy 的 LLM Wiki（让 LLM 增量维护、可复利的知识产物）。
CodeGraph · 代码符号 / 文件 / 调用关系 / 影响路径。解决「改了这里会坏哪里」。
该模块复用了开源项目 codegraph 的预索引代码图谱实现。
一句话区分：Chat Memory 记「人和事」，Skill 记「怎么做」，Wiki 记「文档说了什么」，CodeGraph 记「代码怎么连」。四者不能互相替代——把文档塞进 Chat Memory 或用 Skill 记代码结构，都会很快失控。

2. 可见性：分享是明确动作，不是默认泄漏

可见性语义典型用途
private只有 Owner 能读，团队管理员也不行新产生的记忆与 Skill 的默认态
team团队成员可读，Owner / Admin 管理团队通用的架构 Wiki、上线检查表
restricted按 User / Role / Agent 的 ACL 精确授权含敏感信息、只给特定角色
agent定向装配给同团队的某个 agent把「发布 Skill」只给 Release Agent

3. 最有价值的概念：Loadout（配装）

这是它和「聊天记录仓库」最大的差别：记忆不是全局 prompt，而是按 Agent 装配的装备包。

🔭 Scout（查资料）
   ├── 用户访谈 Chat Memory
   ├── 市场研究 Wiki
   └── 竞品分析 Skill

🛠 Builder（写代码）
   ├── 产品 Wiki
   ├── 项目 CodeGraph
   └── Feature Delivery Skill

🧪 Reviewer（挑毛病）
   ├── 历史事故 Chat Memory
   ├── 项目 CodeGraph
   └── Release Checklist Skill
为什么这个设计对：把全部记忆塞给每个 agent，等于让它每次在一堆无关信息里找线索。少给噪音，比多给信息更有效——这也和你配 embedding / 卡召回条数是同一个道理。

4. 冷启动：先读档，再开工

大多数 agent 的第一件工作是重新学习你的项目。这套系统的做法是把你已经付过的学习成本变成存档：

导入什么自动变成
已有代码库CodeGraph（索引符号、文件、调用关系、影响路径）
文档与文件Wiki（结构化页面 + 链接图谱）
过去的对话 SessionSkill + Chat Memory（提取可复用做法与记忆资产）
两个现实约束（官方自己承认）：① Wiki 与 CodeGraph 是异步构建，导入后要等它变 ready，不是立刻可用；② CodeGraph 目前优先支持公开 HTTPS 仓库，私有仓库走 SSH 仍在完善中。

5. 你的落地清单

把这一课变成可执行的三步（按顺序，每步都有验收）：

步骤做什么验收
第一步 · 只做 Chat Memory按第 1–7 课把本地 provider 跑通，配 LLM key，让它抽 L1/search/memories 有结果，recall.context 非空
第二步 · 加一条 Skill把一件你反复做的事（比如「上线前检查」）跑一次，让它提炼成 Skill；确认它有触发边界与验证规则下一个会话里它能被召回并说明「什么时候该用」
第三步 · 再接知识有了真实痛点再上 Wiki / CodeGraph（Docker 三件套或远端形态）agent 能通过工具按需查页面 / 查调用关系，而不是先读完所有文件
顺序为什么不能反：没有 Chat Memory 就跑 Wiki/CodeGraph，你会得到一堆"能搜但用不上"的知识资产——因为你还没解决「这个 agent 是谁、在替谁工作」的问题。装备之前先有角色。

6. 关于那个 benchmark，一句提醒

README 里写 PersonaMem 从 48% 提升到 76%（相对 +59%）。这是厂方自述、单 benchmark、没有第三方复现。它说明作者认为主要收益在长期用户建模，但不代表你装上就有 59% 的提升——真正的收益取决于你往里放了什么、以及给哪个 agent 配了哪些。

结课自测

🎓 十一课结束。你现在应该具备四件事的能力：

① 拿到任意一篇 TDAI 教程，30 秒判定它走哪条形态；
② 在本机把 gateway 起起来，并用四道门证明它真的在记东西；
③ 沿诊断树从症状走到根因，而不是重装一遍；
④ 说清四类资产的区别，并给自己排出「先 Chat Memory、再 Skill、最后知识」的落地顺序。
