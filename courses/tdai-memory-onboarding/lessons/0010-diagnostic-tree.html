课程 0010 · 诊断树：从症状走到根因

TencentDB Agent Memory 入门 · 第 10 课 · 预计 16 分钟

前九课给了你知识和一把坑。这一课把它变成可执行的判断顺序——从你观察到的症状出发，每一步只问一个问题、只跑一条命令，走到唯一根因。

本节目标：拿到任意一个「它不工作」的描述，能沿树走到根因，而不是重装一遍碰运气。

总入口：先分三个岔

症状是什么？
├─ 服务起不来 / 端口报错 ─────────► 分支 A
├─ 服务活了，但对话里像没记忆 ───► 分支 B
└─ 记忆确实在，但用起来不对 ─────► 分支 C

分支 A · gateway 起不来

先跑：

netstat -ano | grep ":8420" | grep LISTENING
看到什么根因解药
EADDRINUSE，且有 PID 在 LISTENING残留进程占着端口（tsx 是 shell → cli → node 三层链，杀一层不等于清干净）按 PID 确认是自己的进程再逐个杀，别按进程名批量杀 node
Error: The service was stopped（esbuild）用了 node --import tsx改用 node ./node_modules/tsx/dist/cli.mjs src/gateway/server.ts
`Cannot find module '...integrations/factory.js'` 之类私有子模块缺失，standalone 模式回退这是正常噪声，别管它，继续看 /health
node 版本报错低于 22.16升 node（原生模块与 jieba 需要）

分支 B · 服务活了，但像没记忆

按顺序跑这三条，每条都能把范围砍掉一半：

# ① 活着吗
curl -s localhost:8420/health
# ② 写进去了吗
curl -s -XPOST localhost:8420/capture -H "Content-Type: application/json" \
  -d '{"user_content":"诊断探针","assistant_content":"ok","session_key":"diag"}'
# ③ 能搜回来吗（唯一不会骗人的门）
curl -s -XPOST localhost:8420/search/conversations -H "Content-Type: application/json" \
  -d '{"query":"诊断探针","limit":3}'
结果根因下一步
① 就失败服务没起来回分支 A
② l0_recorded:0写入链路断（极少见）看 gateway 日志里的 L0 写入记录
② OK 但 ③ total:0检索没命中：查询词与内容无共同分词结果，或写的是另一个数据目录换内容里出现过的原词再搜一次；核对启动日志里的 dataDir
③ 有结果，但 /recall 空L1 没抽出来（L0 与 L1 是两件事）进分支 B2

分支 B2 · L0 有、L1 恒空

检查根因解药
TDAI_LLM_API_KEY 是否为空没配模型，L1 抽取没法做配 TDAI_LLM_API_KEY / _BASE_URL / _MODEL
MEMORY_PROMPT_MODE 是 code 还是 chat模式与内容不匹配（用 code 模式聊日常 → 抽出 0 条）闲聊改 chat，工程协作保持 code
对话里有没有可抽的东西纯寒暄 / 纯工具调用换成含事实、约束、决策的对话再试
是否重复说同一件事去重把新条目合并了这是设计不是 bug；换新事实再试
这条分支上最大的陷阱：别用 tasksCompleted 判断。/health 里它可能一路涨到 5、tasksFailed 是 0，而 l1_records 仍是 0。只认 /search/memories 有结果。

分支 C · 记忆在，但用起来不对

症状根因解药
同义词搜不到（说「情报系统」，记的是「情报平台」）没配 embedding，只走 FTS5 + jieba 关键词配齐 embedding 四元组；用 /health 的 embeddingService 确认变 true
配了 embedding 但还是搜不到同义词四元组缺一项 → 静默降级检查 apiKey / baseUrl / model / dimensions 是否都在
分数很高却召回不相关拿 BM25 分数当绝对阈值卡只用它排序；要卡阈值先在自己库上采样看分布
刚说完立刻搜不到回流是异步的（第 7 阶段在转发之后）等一两秒或触发一次 capture 后再搜
停进程后读库能读，跑着时读到 0 行WAL 未 checkpoint这不是故障；验收只信 API

分支 D · Hermes 侧完全没反应

这是最容易误判的一支，因为它三种失败长得一模一样：对话正常，只是记忆没进来。

# 唯一的判据：Hermes 认不认这个 provider
cd "$HERMES_HOME/hermes-agent" && venv/Scripts/python.exe -c \
  "from plugins.memory import discover_memory_providers as d; [print(n,a) for n,_,a in d()]"
输出根因解药
列表里没有 memory_tencentdb目录名不是下划线 / 放错 HERMES_HOME / 没放 __init__.py目录名必须等于 plugin.yaml 的 name；确认用的是 $HERMES_HOME 而不是 ~/.hermes
出现但 False依赖不全或 gateway 不可达看 $HERMES_HOME/logs/memory_tencentdb/gateway.stderr.log
出现且 True，但还是没记忆config.yaml 里的 memory.provider 没切过去加 memory.provider: memory_tencentdb 后重启 Hermes
工具列表里没有 memory 搜索工具gateway 不可达且未设 MEMORY_TENCENTDB_GATEWAY_CMD / _PORT → tools 返回空设上其中一个，让工具乐观注册

分支 E · 团队版（8096 / 8125）

症状根因解药
面板 8125 打不开 / 提示 Panel API 未启动hub 容器不 healthydocker logs tdai-memory-hub，多半是 REMOTE_INSTANCE_URL 或 LLM_BASE_URL 配错
业务用户看不到「新建团队」权限设计：建 Team 只对 admin 开放让 admin 建好并把你加入；或用自己的 key 调 team/create
API 建了用户，面板里看不到user/create 只建账号不入队再调一次 team-member/add
改了 proxy 的 config.yaml，重启就没了start-proxy.sh 每次覆写生成的配置用 PROXY_CONFIG_DIR 指向自己维护的目录
Claude Code 不弹 team/agent/task 表单PROXY_ENABLE_SESSION_INIT=1 没开用 PROXY_FULL_STACK=1 ./start-proxy.sh 重启
上游 400 unknown tool ""客户端 preset 没挂表单用的 UI tool，proxy 塞的 fake tool_call 被拒开 headless bypass：body.tools 非空但无该 tool 时直接透传
上游 400 reasoning_content must be passed backfake 消息没带该字段，或序列化时被抹掉塞非空占位串；用 PROXY_DEBUG_DUMP_INBOUND / DUMP_BODY 对比进出站

一张收敛表：症状 → 一句话根因

症状根因（一句话）
npm install 失败你在默认分支上，那里没有 package.json
gateway 崩在 esbuild用了 --import tsx 而不是 tsx CLI
数据找不到TDAI_DATA_DIR 写成了 MSYS 路径，跑到盘根去了
端口被占但进程查不到tsx 的三层进程链没清干净
库里读到 0 行进程还活着，WAL 没 checkpoint
tasksCompleted 涨了但没记忆LLM 抽取失败被吞，任务仍记完成
同义词搜不到只有 FTS + jieba，没上 embedding
配了 embedding 却没用四元组缺一项，静默降级
Hermes 静默无记忆四个 header 缺一 → session bypass
provider 装了不生效目录名不是 memory_tencentdb，或放错了 HERMES_HOME
