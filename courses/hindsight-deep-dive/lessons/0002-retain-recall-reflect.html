课程 0002 · 三核心操作：retain / recall / reflect

Hindsight 从入门到精通 · 第 2 课 · 预计 13 分钟

Hindsight 的全部能力归结为三件事：存进去（retain）、找出来（recall）、想明白（reflect）。这一课把三者的分工、输入输出、代价差异讲清楚——分不清这三者，就永远调不好记忆。

本节目标：能准确说出三个操作各自做什么、什么时候用哪个、以及哪个最贵。

1. 三者对比（核心表）

用途retain：存信息recall：找信息 / reflect：推理信息
输入原始文本、对话、文档recall 是搜索词；reflect 是问题
输出记忆 ID（存了就行）recall 是排序后的条目；reflect 是成段回答
用 LLM 吗用（抽取事实）recall 不用；reflect 用（生成回答）

2. Retain：存，但不是「原样存」

你丢进去一段文本，Hindsight 用 LLM 把它拆成结构化的事实、识别实体、建立关联。所以 retain 不是零成本的写入——每条都过一遍模型。这也是为什么「存什么」要克制。

// 工具用法（也可自动 retain 每轮对话）
hindsight_retain(content="用户偏好中文回答", context="user preference")
自动 vs 手动：auto_retain 默认开启，每轮对话自动存（含工具调用）。自动存是「广撒网」，手动 hindsight_retain 是「重点标注」——重要结论主动存，带 tags 便于日后精准检索。

3. Recall：找，且不需要 LLM

recall 是纯检索：多路策略并行搜索 + 融合 + 重排。因为不调用 LLM 生成，它快且便宜。返回的是排序后的 facts + observations。

hindsight_recall(query="这个项目的部署方式")
注意一个常见困惑：recall 返回空不代表坏了——记忆需要至少一次 retain 周期，而且抽取本身是 LLM 调用（有延迟）。刚存的事实，下一轮才查得到。

4. Reflect：想，最贵但最有用

reflect 会召回相关记忆与观察，应用 bank 的 disposition（性格倾向），让 LLM 基于证据推理出一个回答。它不是「搜索」，是「跨记忆的综合推理」。

hindsight_reflect(query="我在这个项目上形成了哪些稳定的工作习惯？")

recall 给你「相关的事实清单」，reflect 给你「一段有理有据的结论」——这是 Hindsight 相对其他 provider 最独特的能力。

5. 什么时候用哪个

要记住事retain（或依赖 auto_retain 自动存）
要查具体事实recall —— 快、便宜、给清单
要综合判断reflect —— 慢、贵、给结论
