课程 0004 · 事实三类型：observation / world / experience

Hindsight 从入门到精通 · 第 4 课 · 预计 14 分钟

这是 Hindsight 最反直觉、也最容易踩坑的设计：它把记忆分成三层——原始事实（world / experience）和整合后的观察（observation）。而 recall 默认只返回 observation。不懂这个，你会以为「我存的东西怎么查不到」。

本节目标：分清三种事实类型，理解为什么默认只给观察，以及什么时候该放开。

1. 三种事实类型

world关于外部世界的事实。例：项目用 Vite 构建、服务器是 CentOS 7
experience关于经历/交互的事实。例：用户上次要求用中文回答、某次调试花了很久
observation整合层：在原始事实之上归纳出的、去重且有证据支撑的稳定结论

2. 观察是怎么来的

retain 进来一堆原始事实后，Hindsight 在后台做 consolidation（整合）：把散落的、重复的、相似的事实归纳成一条「观察」，并带上证据计数与新鲜度信号。

# 原始事实（多条，零散）
world: 用户周一用中文提问
world: 用户周二用中文提问
world: 用户周三要求中文回答

# ↓ 整合成一条观察
observation: 用户偏好用中文交流（证据 3 条，近期活跃）
为什么要这层？因为每 token 的信息密度。与其塞 3 条原始事实占额度，不如塞 1 条已经归纳好的观察。对「每轮自动注入上下文」这种场景，观察更省、更准、更少自相矛盾。

3. 关键行为变更：recall 默认只给 observation

旧行为recall 返回全部三种类型信息全，但冗余重复
现默认recall_types = observation省 token，只给结论层
想放开设 recall_types = observation,world,experience连原始证据一起看
// ~/.hermes/hindsight/config.json（或 $HERMES_HOME/hindsight/config.json）
{
  "recall_types": "observation,world,experience"
}
这个设置同时影响两条路径：自动 recall（每轮注入）和 hindsight_recall 工具——工具没有 per-call 的 types 参数，两者读同一个配置。所以收紧默认会同时收紧两处。

4. 什么时候该放开

用默认日常问答、想要干净的结论 —— 大多数情况够用
放开需要溯源（这条结论依据哪些原始事实）、或观察还没整合出来急需原始数据
注意放开后 token 消耗上升，且可能拿到互相重复的原始事实
