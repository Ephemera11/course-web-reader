课程 0008 · 安装与三种模式：cloud / local_embedded / local_external

Hindsight 从入门到精通 · 第 8 课 · 预计 15 分钟

Hindsight 有三种运行模式，决定了你的记忆数据存在谁那里、以及每次 retain 会经过谁。这是隐私与成本的第一个岔路口。你当前用的是 local_external，这一课把它和其他两种摆在一起看。

本节目标：说清三种模式的差异与适用场景，并会检查自己的当前模式是否在正常工作。

1. 三种模式对比

cloud记忆存在 Hindsight 云（api.hindsight.vectorize.io）零运维，需 API key，按量付费
local_embeddedHermes 自己拉起本地 Hindsight 守护进程数据全本地；需给 LLM key（抽取要用模型）
local_external连你自己部署的 Hindsight 服务数据与算力自主，需要你运维那个服务

2. 安装与激活（别踩这两个坑）

# 1) 从插件目录安装
hermes plugins install hindsight

# 2) 设为激活的记忆 provider
hermes memory setup
#    或手动：hermes config set memory.provider hindsight
坑一：记忆 provider 是由 memory.provider 激活的，不是 plugins.enabled。所以 hermes plugins enable hindsight 并不会激活它——装完要在安装提示里选 yes，或跑 hermes memory setup。
坑二：插件读自己的 config.json（$HERMES_HOME/hindsight/config.json，以及遗留的 ~/.hindsight/config.json）和 .env 里的 HINDSIGHT_* 变量，不读 config.yaml 的 memory.hindsight.*——写在那里会被忽略。

3. 你的当前配置

// C:\Users\WTY\AppData\Local\hermes\hindsight\config.json
{
  "mode": "local_external",
  "api_url": "http://127.0.0.1:8888"
}

你的架构是：Hermes 插件 → 本地 Hindsight 服务（:8888）→ PostgreSQL。数据不出本机，代价是那个服务要你自己照看。

4. 健康检查（随时自查）

# 服务活着吗
curl http://127.0.0.1:8888/health
# → {"status":"healthy","database":"connected",...}

# 有哪些 bank、多少事实
curl http://127.0.0.1:8888/v1/default/banks

# 交互式 API 文档
# 浏览器打开 http://127.0.0.1:8888/docs
两个命令记住就够：hermes memory status 看 provider 是否激活、curl .../health 看本地服务是否健在。出问题先跑这两个。

5. 隐私须知（重要）

cloud / local_external每轮对话、以及你写入内置 MEMORY/USER 的每条内容，都会发到对应服务、进到它写入的每个 bank
local_embedded数据留在本地，但抽取仍需调用 LLM（用你配的模型 key）
红线凭据、密钥类内容不要指望插件脱敏兜底——敏感信息压根别交给记忆系统
