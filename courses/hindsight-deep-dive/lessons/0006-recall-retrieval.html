课程 0006 · Recall 内部：四路检索、融合与重排

Hindsight 从入门到精通 · 第 6 课 · 预计 14 分钟

recall 为什么能找得准？因为它不是「一路搜索」，而是四路并行 + 融合 + 重排。理解这条流水线，你才能看懂那些 score，也才知道 recall_min_scores 该怎么调。

本节目标：说出四路检索各管什么、为什么要融合重排，以及如何用 score 阈值清掉噪声。

1. 四路检索并行跑

semantic语义向量相似 —— 意思相近但用词不同的能找回
keyword关键词匹配 —— 专有名词、ID、精确术语靠它
graph知识图谱遍历 —— 通过实体关系找到「相关但字面不同」的记忆
temporal时间维度 —— 最近发生的、或某时间段的记忆

四路各有所长：搜「那个课程站」靠语义；搜「4893」靠关键词；问「和 course-web-reader 相关的所有事」靠图；问「上周我们聊了什么」靠时间。

2. 融合与重排

① 融合四路结果合并（fuse），同一条被多路命中的权重更高
② 重排reranker 模型对候选重新排序（注意：它只排候选，不判断「是否相关」）
③ 截断按 recall_max_tokens（默认 4096）截取

3. 关键认知：recall 会「排序」，但不会「判断相关性」

这是最容易误判的一点。问一个和记忆库完全不相关的问题，recall 仍会返回「最不坏的那批」——它只负责排序，不负责说「这题没答案」。所以你看到结果里有东西，不代表它真的相关。
// 解法：设最小分阈值，让「没被该路召回」的结果被拒
{
  "recall_min_scores": { "semantic": 0.5 }
}

设哪一路必须看自家 bank 的实测分布，不能照抄别人的数字。本课在自己的 bank（中文、内容高度同质）上实测：reranker 对完全无关的查询照样给 0.99+，毫无区分度；而 semantic 在无关查询上有大量 None（说明该路根本没召回它）。所以这里该设的是 semantic，不是 reranker。

4. 各 score 字段的含义

reranker重排模型给的分总有值，但实测不区分相关性（无关查询也 0.99）
semantic向量相似度多语言 bank 上区分度最好；未被该路召回时为 null
keyword关键词匹配分只剪自己那一路
final最终综合分服务端保证有值
调阈值前先看自家 bank 的实际分数分布。而且要注意：设了某一路的阈值，只影响那一路的检索臂——被其他路命中的结果仍会回来（该路分数为 null）。插件还会校验每条结果是否真的报告了被设阈值的那一段分数，不报告的会被拒。

5. 其他 recall 相关旋钮

recall_budget检索彻底度：low / mid（默认）/ high
recall_max_input_chars自动 recall 的查询截断长度（默认 800）
recall_sync默认 false：后台跑，下一轮注入（更快）；true 则对当前消息同步检索
