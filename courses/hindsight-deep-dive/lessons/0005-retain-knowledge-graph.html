课程 0005 · Retain 内部：知识图谱与实体解析

Hindsight 从入门到精通 · 第 5 课 · 预计 14 分钟

retain 不是「写文件」。你把一段话丢进去，Hindsight 会用 LLM 把它拆成事实、认出实体、连成图。理解这个过程，你才知道为什么「怎么存」比「存多少」更影响检索质量。

本节目标：说清 retain 的处理链路（文本 → 事实 → 实体 → 图），并能据此写出「好存」的记忆。

1. Retain 的处理链路

① 切分长文本被拆成可处理的单元（文档 → 段落）
② 抽取LLM 把文本转成结构化事实（world / experience）
③ 实体解析识别提到的人/项目/工具，并归一到同一实体
④ 建图把事实与实体连成关系边，形成知识图谱
⑤ 整合后台 consolidation 归纳出 observation（下一课详讲）

2. 实体解析在解决什么

同一件事在不同对话里可能有不同说法：

course-web-reader
C:\Users\WTY\Documents\course-web-reader
这个课程阅读器项目
那个读课程的网站

实体解析就是把这些归一到同一个节点。只有这样，当你问「课程站怎么部署」时，图检索才能把散落在几十条记忆里的相关信息通过这个节点串起来——这是纯向量检索做不到的。

所以「一致性命名」很重要：同一个项目/工具，尽量用同一个名字（而不是每次换说法）。实体归一越干净，图检索越有效。

3. 什么算「好存」的记忆

好陈述句，主体明确：「course-web-reader 项目用 Vite 构建，部署在 Vercel」抽取干净，实体清晰
好带因果/条件：「因为 Vercel 私有仓库会 Blocked，所以仓库改成 public」能建关系边
差碎片指令：「改一下那个」无主体，抽不出有用事实
差大段闲聊原文，无重点抽取噪声多，稀释检索

4. 手动 retain 时的两个杠杆

// ① context：给这次存储一个语境标签
hindsight_retain(
  content="用户偏好中文回答",
  context="user preference"
)

// ② tags：打标签，日后可精准过滤
hindsight_retain(
  content="course-web-reader 必须用 public 仓库才能自动部署",
  tags=["project-x", "deploy"]
)
tags 是「不拆 bank 也能隔离」的手段：同一 bank 里，用 recall_tags 只捞某个项目/话题的记忆。银行账户里的分账本，而不是开新的银行。
