课程 0009 · 配置调优实战：budget / types / min_scores / tags

Hindsight 从入门到精通 · 第 9 课 · 预计 14 分钟

前 8 课是「懂」，这一课是「调」。四个最常用的旋钮——budget（挖多深）、types（看哪层）、min_scores（多严）、tags（看哪块）——组合起来能解决绝大多数「检索不准/太吵/太贵」的问题。

本节目标：会用这四个旋钮，并知道每个旋钮各解决什么症状。

1. 症状 → 旋钮对照表

结果太少/漏了recall 挖得不够深调高 recall_budget（mid → high）
结果太吵/不相关阈值没设，什么都被捞回来设 recall_min_scores
只想要结论塞了太多原始事实保持 recall_types = observation
只关心某项目检索范围太大recall_tags 过滤
注入太长/太贵返回量太大调低 recall_max_tokens

2. recall_budget：彻底度

low最快最省，适合日常闲聊
mid默认，平衡
high挖得最深，适合「怎么找都找不到」时排查

3. recall_min_scores：把噪声清成空

// 最实用的单条调优：让没被语义路召回的无关结果被拒
{
  "recall_min_scores": { "semantic": 0.5 }
}
怎么定阈值？只有一条正路：实测自家 bank 的分数分布，别照抄。本课在自己 bank 上的实测（中文、内容同质）：reranker 无区分度——无关查询也给 0.994~0.999；semantic 才有区分度——相关查询 18/30 有值（0.673~0.878），无关查询仅 4/14 有值（0.731~0.758）。设 {"semantic": 0.5} 后：相关 30→18、无关 14→4，砍掉约七成噪声。官方的 {"reranker": 0.25} 建议在多语言 bank 上无效，正是因为 reranker 不区分相关性。

4. tags：不拆 bank 做隔离

// 存的时候打标（retain_tags 默认标签 + 工具级 tags 合并）
hindsight_retain(content="...", tags=["project-x"])

// 查的时候过滤（JSON 列表或逗号分隔字符串都行）
{ "recall_tags": "project-x, deploy" }

// 匹配模式
{ "recall_tags_match": "any" }   // any / all / any_strict / all_strict
注意 reflect 的 tags 是独立的：reflect_tags 与 recall_tags 是两个键。不设 reflect_tags 时，reflect 用整个 bank；recall_tags 不会影响 reflect。

5. 一个可用的起步配置

// $HERMES_HOME/hindsight/config.json
{
  "mode": "local_external",
  "api_url": "http://127.0.0.1:8888",
  "recall_budget": "mid",
  "recall_types": "observation",
  "recall_min_scores": { "semantic": 0.5 },
  "recall_max_tokens": 4096
}
改完要重启 Hermes 才生效（配置文件不像 provider 有热加载）。改前先备份原文件。
