课程 0011 · 实战：设计你自己的记忆体系

Hindsight 从入门到精通 · 第 11 课（收官）· 预计 16 分钟

前 10 课拆开了讲，这一课把它们组装成一套属于你的、可落地的记忆体系——基于你的真实环境（local_external、bank=hermes、4893 条事实、mission 为空），并配一份排查手册。

本节目标：产出一份自己的「记忆体系设计 + 优化清单 + 排查手册」。

1. 第一步：先明确你用它做什么

个人助手型记住偏好、项目、决策 —— 单 bank 合理，重点是 tags 与 mission
多项目型项目之间互不干扰 —— 用 {project} 模板或 tags 隔离
多用户型多人共用 —— 必须 {user} 或按用户拆 scope，防串味

2. 第二步：给你现有 bank 的三项优化

结合你的实测快照，三处可以马上动手（改前先备份配置）：

① 补 mission现在是空 —— reflect 没有视角框架写一句明确身份与关注面的话
② 设 min_scores未设阈值 —— 无关查询也会返回噪声先看自家分数分布，再定阈值
③ 定 disposition三档都是默认 3按用途调：技术判断调高 skepticism
// 建议的配置起点（$HERMES_HOME/hindsight/config.json）
{
  "mode": "local_external",
  "api_url": "http://127.0.0.1:8888",
  "recall_budget": "mid",
  "recall_types": "observation",
  "recall_max_tokens": 4096
}

3. 第三步：决定隔离策略（bank vs tags）

默认建议：不要急着拆 bank。你已经在单 bank 里积累了 4893 条事实，图关联是资产。只有当「检索噪声明显来自不同项目/人」时才拆；否则先用 tags + recall_tags 做软隔离——保留跨话题关联，又能精准过滤。
// 软隔离示例：主题标签
hindsight_retain(content="...", tags=["project:course-web-reader"])

// 检索时只捞这个项目
{ "recall_tags": "project:course-web-reader" }

4. 第四步：存什么（这是最影响质量的）

主动存稳定偏好、已定决策、踩过的坑、项目关键事实 —— 带 tags
靠自动日常对话由 auto_retain 兜底，不必逐句手动存
别存一次性琐碎指令、密钥凭据、大段无重点原文

5. 排查手册（收藏这段）

recall 为空刚存就查 / 抽取还没跑完等一个处理周期再查；确认 provider 已激活
recall 很吵没设 min_scores设 recall_min_scores，并按 tags 收窄范围
找不到该有的budget 低 / 类型被收窄临时调 high budget；必要时放开 recall_types
服务连不上本地 Hindsight 没跑curl .../health 确认；再查 api_url 是否对
改了配置不生效没重启 / 写错位置重启 Hermes；确认改的是 hindsight/config.json
你已掌握的能力：① 三层记忆体系定位；② 三核心操作；③ bank 隔离与组织；④ 事实三类型与整合层；⑤ retain 的图谱化；⑥ recall 四路检索与调优；⑦ consolidation 分组；⑧ 三种运行模式；⑨ 四大配置旋钮；⑩ reflect + disposition + mission；⑪ 完整体系设计与排查。

小测

🎓 课程到此结束。你已经从「装好了但不懂」走到「能设计、能调优、能排障」。下一步：按上面第二步给你的 bank 补上 mission、定好 min_scores 阈值——这两件小事就能明显改善日常体验。有疑问随时问。
