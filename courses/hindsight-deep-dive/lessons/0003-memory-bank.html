课程 0003 · 记忆 Bank：隔离与组织

Hindsight 从入门到精通 · 第 3 课 · 预计 13 分钟

Bank（记忆库）是 Hindsight 的隔离单元：bank 之间互不可见，检索只在自己 bank 内进行。规划 bank 就是规划「记忆的边界」——这是从入门到精通最需要判断力的一步。

本节目标：理解 bank 的隔离语义、多 bank 的读写规则，以及你的场景该用一个还是多个 bank。

1. Bank 是什么

一个 bank 就是一套独立的知识图谱 + 观察集合，有自己的 ID、mission、disposition 和事实集。默认 bank ID 是 hermes——也就是你现在用的这个（4893 条事实）。

# 列出你的 banks（只读）
curl http://127.0.0.1:8888/v1/default/banks
# → banks: [hermes]  total: 1

2. 主 bank 是怎么选出来的

优先级从高到低：

① 仓库配置受信仓库里的 .hindsight/config.toml —— 让单个项目拥有专属记忆
② 模板bank_id_template —— 用占位符动态生成 bank 名
③ 静态HINDSIGHT_BANK_ID 环境变量 或 bank_id 配置

3. bank_id_template：按维度自动分区

// 可用的占位符
{profile} {workspace} {project} {platform} {user} {session}

// 例 1：按 Hermes profile 隔离
bank_id_template = "hermes-{profile}"

// 例 2：每个 git 仓库一个 bank
bank_id_template = "{project}"
占位符空值会优雅塌缩：比如 hermes-{user} 在没有 user 时会退化成 hermes。{project} 取的是当前 git 仓库名，同一仓库的所有 worktree 解析为同名；在仓库外（或根目录是 home）则为空。

4. 多 bank：读写规则不同

additional_banks额外 bank，按优先级写入会写，也会被 recall 到
recall_additional_banks只读的额外 bank只被检索，永不写入
mirror_to_own_bank开启后额外镜像写一份到 bank_id双写，冗余但保险

recall 会同时搜所有相关 bank（主 bank + 写入 bank + 只读 bank），各自按配置的预算检索，结果按顺序合并、按文本去重。而 reflect 只用主 bank——这点很容易忽略。

5. 你该用一个还是多个 bank？

单个 bank个人助手、记忆之间有关联、想让 reflect 看到全景 —— 你现在就是这种，合理
按项目分多个互不相关的项目，怕互相污染检索结果 —— 用 {project} 模板
按人分多人共用一个 Hermes（团队/客服）—— 用 {user} 彻底隔离
取舍的本质：bank 分得越细，检索越精准、噪声越少；但跨 bank 的关联就丢了（reflect 只看主 bank）。单 bank 记忆更「融会贯通」，代价是检索时可能捞到无关内容——这时该用 tags 而不是拆 bank（下一课讲）。
