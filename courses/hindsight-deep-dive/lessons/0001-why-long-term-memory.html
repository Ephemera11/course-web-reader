课程 0001 · 为什么 LLM 需要长期记忆：Hermes 的三层记忆体系

Hindsight 从入门到精通 · 第 1 课 · 预计 12 分钟

你已经把 Hindsight 接进 Hermes 了，但可能没想过：为什么光有上下文窗口不够？这一课建立全局心智模型——Hermes 的记忆不是「一个东西」，而是三层各司其职的体系，Hindsight 是其中最厚的一层。

本节目标：说清 Hermes 三层记忆的分工，并把 Hindsight 放进正确的位置。

1. 根本问题：模型本身没有记忆

LLM 是无状态的。每次对话它只看到「这次请求里塞给它的文本」——也就是上下文窗口。会话关掉，一切归零。想让 Agent 记住「用户偏好中文」「这个项目用 Vite」，就得把事实存到模型之外，再在需要时塞回去。

难点在「需要时」：存得越多，越不可能全塞进上下文。于是就需要检索。

2. Hermes 的三层记忆

① 会话历史当前这次对话的完整过程自动，仅限本次会话（可压缩）
② 内置 MEMORY / USER两个手写文件，每轮全量注入上下文精确可控，但容量极小、必须人工维护
③ 外部 provider（Hindsight）海量长期记忆，按相关性检索后注入自动积累，容量大，但有检索误差与成本
关键认知：内置记忆是「每轮必带的小抄」，Hindsight 是「按需查阅的档案库」。这也是为什么装了 Hindsight，内置 MEMORY.md 仍然照常工作——两者并存互补，不是二选一。

3. Hindsight 是什么

一句话：一个带知识图谱的长期记忆服务。它不是简单地把文本存成向量，而是在 retain 时用 LLM 抽取事实、识别实体、建立关联，形成图结构；检索时用多路策略并行找、融合、重排。

能力知识图谱 + 实体解析 + 多策略检索 + 跨记忆推理（reflect）
形态Hermes 记忆 provider 插件（Vectorize 维护，从插件目录安装）
工具hindsight_retain / hindsight_recall / hindsight_reflect
