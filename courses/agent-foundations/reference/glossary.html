Agent 术语表

速查本工作区每节课都会用到的核心名词。定义来源于 Anthropic《Building Effective Agents》及主流共识。每次新课都遵循此表。

Agentautonomous agent
在循环中由模型自身动态决定流程、调用工具、根据环境反馈（工具结果/执行结果）推进任务、知道何时停止的系统。与 Workflow 的根本区别是：谁掌控流程。
自主性循环
Workflowpredefined path
LLM 与工具通过开发者写死的代码路径被编排的系统。流程可预测、一致，但缺乏灵活性。例：固定步骤链、路由、并行。
可预测代码编排
Augmented LLM增强型 LLM
Agentic 系统的基本积木：一个 LLM，被增强了检索（retrieval）、工具（tools）、记忆（memory）能力。模型自己决定何时搜索、调哪个工具、记什么。
积木
Prompt chaining提示链
把任务拆成固定子步骤，每个 LLM 调用处理上一步输出；可在中间加程序化「闸门」检查是否跑偏。用延迟换准确率。
workflow
Routing路由
先分类输入，再把它导向专门的后续处理。适合有明显不同类别、分开处理更好的复杂任务。
workflow
Parallelization并行化
LLM 同时处理任务并程序化聚合输出。两种变体：分片（sectioning）把任务拆独立子任务并行；投票（voting）同一任务多次运行取优。
workflow
Orchestrator-workers编排-执行
中心 LLM 动态拆解任务、委派给 worker LLM、再综合结果。与并行化的关键区别：子任务不是预先定义，而是编排器按输入现定。
workflow
Evaluator-optimizer评估-优化
一个 LLM 生成响应，另一个 LLM 评估并给反馈，循环迭代直至达标。适合有清晰评估标准、迭代能显著提质的场景。
workflow
Agent loop自主循环
Agent 的核心运行机制：感知→推理/规划→行动（调工具）→观察结果→再推理……直到任务完成或触发停止条件（如最大迭代次数）。
循环自主性
Tool / Function calling工具调用
模型通过结构化接口调用外部能力（查数据库、调 API、跑代码）。工具的定义与文档写得是否清晰，直接决定 Agent 成败。
接口
Memory记忆
让 Agent 跨步骤/跨会话保留信息的能力。短期（本轮对话上下文）与长期（外部存储）之分。属于 Augmented LLM 的增强之一。
增强
ReAct推理+行动
Yao et al. 2022 提出的范式：模型交替进行「推理（Reason）」与「行动（Act）」，行动后观察（Observe）结果再继续。现代 agent loop 的理论源头。
理论源头
Autonomy vs Predictability自主-可预测权衡
Agent 用延迟与成本换取性能与灵活性；Workflow 用灵活性换可预测与一致。能简单解决就别上 Agent——这是首要原则。
取舍
Stopping conditions停止条件
让 Agent 循环终止的机制：模型自报完成、最大迭代熔断（MAX_ITER）、任务达成校验、人工 checkpoint、错误预算。绝不只信模型「自觉停」——必须代码层兜底防无限循环。见 课程 0002。
循环护栏
Memory: short vs long记忆：短期/长期
短期=每轮重传给 LLM 的 messages 数组（活在上下文窗口，受 token 上限）；长期=外部存储（Redis/DB/向量库），模型经 tool 调用读取。你后端的缓存与数据库天然就是 Agent 的长期记忆后端。见 课程 0002。
增强存储
ACIAgent-Computer Interface
「代理-计算机界面」类比（Anthropic 附录 2）。提醒：工具接口应像人机界面（HCI）那样投入设计——格式要让模型易写可靠（避开 JSON 转义、diff 行数等坑）、用 poka-yoke 防误用、用大量样例测试模型实际用法。直接决定 Agent 成败。见 课程 0003。
工具接口
Tool definition工具定义三要素
一个工具 = 契约：① name（动词化、无歧义）② description（给模型的提示词，写清用途 + 何时用/不用，应获与主提示同等的打磨）③ input_schema（JSON Schema 收紧参数）。模型据此自主决定调用时机与参数。见 课程 0003。
