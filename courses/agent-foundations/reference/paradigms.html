Agent 架构范式速查

一张图看懂「何时用什么」。骨架来源：Anthropic — Building Effective Agents。先简单，复杂仅当简单方案不够时才上。

谁控流程？ 代码写死 → Workflow ｜ 模型自定 → Agent 核心权衡 延迟/成本 ↔ 性能/灵活性
Workflows · 流程由代码编排（可预测、一致）
Prompt chaining提示链
用：任务能干净拆成固定子步骤
不用：步骤间强依赖、需灵活分支
输入 → LLM① → 闸门检查 → LLM② → … → 输出
Routing路由
用：输入有清晰不同类别，分开处理更好
不用：类别模糊、分类不准
输入 → 分类LLM → 分支A / 分支B / 分支C
Parallelization并行化
用：子任务可并行，或多视角投票提置信
不用：步骤必须串行依赖
输入 → ┬ LLM-a ┐ ├ LLM-b ┼→ 聚合 └ LLM-c ┘ (或同任务投票)
Orchestrator-workers编排-执行
用：事先猜不到要拆哪些子任务（如改哪些文件）
不用：子任务固定可知（那用并行化）
输入 → 编排LLM → 动态派活 → worker×N → 综合
Evaluator-optimizer评估-优化
用：有清晰评估标准、迭代能显著提质
不用：质量难量化、反馈无价值
生成LLM ⇄ 评估LLM（反馈循环直到达标）
Autonomous Agent · 模型在循环中自主控流程
Agent loop自主循环
用：步骤数难预测、无法硬编码固定路径的开放问题
不用：简单任务——成本高风险大、错误会累积
目标 → 感知 → 推理 → 行动(调工具) → 观察结果 → 再推理 → … → 停止条件
