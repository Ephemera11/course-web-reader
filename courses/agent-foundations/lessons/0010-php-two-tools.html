课程 0010 · 动手第④步：PHP 双工具 + 模型选路

Agent Foundations · 动手阶段第 4 课 · 预计 15 分钟

Agent 有了一个工具不算 Agent——真正的 Agent 要在多个工具之间自己选。这节课加 calculator（安全四则运算），Agent 被问"3 小时后是几点"时能自己决定：先算时间、再调 get_time？还是反过来？

验收标准：同时注册 get_time 和 calculator，Agent 被问"3 小时后是几点"时能先算时间再调工具。两步都正确。

1. 两个工具的定义

$tools = [
    [
        'name' => 'get_time',
        'description' => '获取当前日期和时间，不需要参数。当被问到「现在几点」时用。',
        'parameters' => ['type'=>'object', 'properties'=>new stdClass, 'required'=>[]],
    ],
    [
        'name' => 'calculator',
        'description' => '安全地计算数学表达式。仅支持 + - * / 和括号。当需要做算术时调用。',
        'parameters' => [
            'type' => 'object',
            'properties' => ['expression' => ['type'=>'string', 'description'=>'数学表达式，如 "3+5" 或 "3*24"']],
            'required' => ['expression'],
        ],
    ],
];

$executors = [
    'get_time' => fn() => date('Y-m-d H:i:s'),
    'calculator' => function($expression) {
        // 安全：只允许数字、运算符、空格和括号
        if (!preg_match('/^[0-9+\-*\/() .]+$/', $expression)) {
            return "错误：表达式包含非法字符";
        }
        return "结果 = " . eval("return $expression;");
    },
];

2. 关键差异：从"一个工具"到"工具集"

一个工具
Agent 只能调 get_time → 问时间之外的请求全部走文本回复。
两个工具
Agent 在 get_time 和 calculator 之间自己选——"调不调、调哪个、传什么参"三个决策第一次完整落地。

循环代码完全不用改——$tools 数组多一条，$executors 多一项，Agent 自动获得选路能力。这就是 Tool Calling 的美妙之处：模型驱动，你的代码只是执行器。

3. 动手：三个测试场景

改 $GOAL，跑 step4.php，观察 Agent 选了哪个工具：

场景 A'现在几点？FINISH' → 应只调 get_time
场景 B'25 乘以 4 等于多少？FINISH' → 应只调 calculator
场景 C'3 小时后是几点？用工具算出来，FINISH' → 可能先 calculator(3*3600) 转换，再 get_time 取当前时间加偏移，或直接推。关键：决策由 Agent 自己定
PHP 工程师直觉：这和你写的「路由分发」完全等价——以前你写 if($action==='queryTime') get_time() elseif(...) calculator()，现在是 LLM 替你做了这个 if/else。Agent 框架本质上就是一个"LLM 驱动的动态路由器"。
