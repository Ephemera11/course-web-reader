课程 0005 · 复杂度光谱：从 Prompt 到 Agent 的选型决策

Agent Foundations · 第 5 章 · 主推源：Anthropic《Building Effective Agents》

前四课你学了「Agent 是什么」「循环怎么转」「工具怎么接」「五种 Workflow 怎么选」。现在只剩最后一个——面对一个真实需求，到底该用简单 Prompt、Workflow、还是全长 Agent？这堂课给你一个可以当场判断的框架。

学完这课你能：面对任何一个业务需求，在 30 秒内判断出最简方案是什么，并说清「为什么不上 Agent」或「为什么必须上 Agent」。

1. 一张光谱：简单 · 可控 · 便宜 ← → 灵活 · 自主 · 贵

Anthropic 把 LLM 系统的「自主度」画成一条连续轴，不是二元开关：

简单 Prompt
Prompt Chaining
Routing / Parallel
Orch-Workers
Autonomous Agent

越往右：模型越自由、能应付的场景越开放，但延迟↑ / 成本↑ / 不可控性↑。Engineering 的目标是能用左边就别往右——每向右挪一步，多一对价。

核心原则（Anthropic 原话）："We recommend starting with the simplest possible solution and only increasing complexity when clearly needed."
翻译：能简单就别复杂。这不仅是成本问题——复杂系统更难调试、更难复现、更可能在生产中悄悄跑偏。

2. 决策树：30 秒走一遍

在下单「上 Agent」之前，先过这 5 问：

Q1. 一个 prompt 能搞定吗？
能 → STOP：写 prompt，别上框架。99% 的「我想要 AI...」到这就够了。
Q2. 步骤固定、顺序已知？
是 → Prompt Chaining。把复杂 prompt 拆成流水线，每步可测可调。
Q3. 输入分几类、每类处理方式不同？
是 → Routing。分类器分到对应专家提示词，简单有效。
Q4. 子任务能无依赖并行，或需投票提稳健性？
是 → Parallelization。扇出→汇总，省钱提速。
Q5. 拆解方式事先无法确定、必须运行时动态决定？
是 → Orchestrator-Workers。这是 Workflow 的天花板。若再加上「评审—生成—迭代修复」的闭环（Evaluator-Optimizer），可覆盖绝大多数生产需求。
Q6. 以上全部不够，你需要模型自己决定「接下来该做什么」、持续多步探索？
是 → 才上 Autonomous Agent Loop。但请确认你没有跳步骤——大多数场景 Q1-Q5 已覆盖。

3. 一张对比表：什么时候该收手

每种方案都有「适合」和「反过来用了会亏」的明确信号。按延迟、可控性、维护成本三轴对比：

方案典型延迟可控性维护成本别用在…
简单 Prompt~1s极高（全写死）低多步推理
Chaining2-5s高（流固定）中低动态拆解任务
Routing1-3s高（分支固定）中低跨类混合任务
Parallel2-4s中高中串行依赖任务
Orch-Workers5-15s中中高简单固定流程
Autonomous Agent10-60s+低（自己定）高一切 Q1-Q5 能覆盖的

4. 给 PHP 工程师的实操启发

回到你的日常技术栈——当你接到一个「用 AI 增强」的需求时，映射关系是：

  • 简单 Prompt ≈ 一个 API 调用，像调 trim() 一样用
  • Chaining ≈ 责任链 / Pipeline 模式，每步可 mock 可单测
  • Routing ≈ 网关路由 / 策略模式，按意图分发到不同 handler
  • Orch-Workers ≈ 主从任务队列，主进程拆任务、worker 并行跑
  • Agent ≈ 一个 while loop 里 LLM 自己决定下一步跑啥——把这当成最后手段

关键纪律：Agent 不是"高级"的代名词，是"拿不到的灵活性的代价"。大多数人犯的错误不是"没用 Agent"，而是"没想清楚就用了 Agent"。

✅ 该上 Agent 的典型信号：
  • 任务结构在运行前无法预知（需要探索而非执行）
  • 需要多步推理且每步结果影响下一步方向
  • 固定 Workflow 会频繁出现「路径覆盖不全」的遗漏
  • 你需要模型在循环里自我纠错（观察→反思→调整→再试）
❌ 不该上 Agent 的典型信号：
  • 你还没把一个最简单的 prompt 版本跑通就想着「架构」
  • 步骤完全可以写死在代码里（Chaining/Routing 够用）
  • 团队还没人能解释 Agent 循环里的每一次工具调用是为什么
  • 需求方说不清「成功标准」——Agent 是为明确目标服务的

小测：检验你真的有判断力了
