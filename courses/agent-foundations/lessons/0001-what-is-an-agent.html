课程 0001 · Agent 到底是什么

Agent Foundations · 概念层第 1 课 · 预计 6 分钟

一句话：Agent = 一个能「在循环里自己决定下一步、并调用工具」的 LLM。 普通 LLM 调用是你问一句它答一句；Agent 是你给个目标，它自己琢磨、动手、看结果、再琢磨，直到干完。

本课目标（一个可验证的小胜）：学完你能用自己的话回答两个问题——① Agent 和普通 LLM 调用差在哪？② Agent 和 Workflow 差在哪？后面有 3 道小测检验。

1. 最小心智模型：四件套

一个最小可用的 Agent，核心由四样东西组成。记这四个词就够了：

模型 Model
做推理与决策的「大脑」
工具 Tools
调 API、查库、跑代码等外部能力
记忆 Memory
跨步骤/跨会话记住信息
循环 Loop
反复「想→做→看」直到完成

Anthropic 把「模型 + 工具 + 记忆」合称为 Augmented LLM（增强型 LLM）——它是所有 Agentic 系统的积木。循环，则是把这块积木变成 Agent 的那一下。

2. 最关键的区分：Agent vs Workflow

这是最容易被绕晕的一点，也是本课重点。区别只有一个问题：流程是谁掌控的？

Workflow（工作流）

流程由开发者写死的代码编排：先调 A、再判断、再调 B……可预测、一致，但死板。

vs

Agent（自主体）

流程由模型自己在循环里决定：下一步调哪个工具、跑几步、何时停，都是它现想的。灵活，但成本高、可能跑偏。

所以是「代码控流程」还是「模型控流程」，一念之差。这也是为什么 Agent 适合步骤数无法提前预测的开放任务，而 Workflow 适合路径固定、要稳定的任务。

3. 一个朴素但重要的提醒

首要原则：能简单解决，就别上 Agent。 Agent 用延迟和成本换性能，且错误会随循环累积。很多时候，优化单次 LLM 调用（加检索、加示例）就够用了；只有简单方案不够时，才加多步 Agentic 系统。框架能帮你起步，但生产环境要懂底层、敢砍抽象层。
