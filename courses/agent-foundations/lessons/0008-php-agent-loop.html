课程 0008 · 动手第②步：PHP 加循环 → Agent 骨架

Agent Foundations · 动手阶段第 2 课 · 预计 15 分钟

上节课你跑通了单轮 LLM 调用——一条 POST，一句回复。这节课给它加一个 while 循环，让它反复调用 LLM、积累对话历史、自己推进目标。这就是 Agent 骨架。

验收标准（0006 路线图第②步）：给模型一个目标，它能在循环里推进——即使只是说着"我需要工具"然后停下。日志里能看到 ≥3 轮迭代。

1. 从"一轮"到"多轮"：差在哪

单轮messages = [user msg] → POST → 回复 → 结束。模型不知道"前面说过什么"，每次都是全新对话。
多轮每轮把模型回复 追加到 messages 数组，下一轮带上完整历史。模型"记得"之前说了什么，能做多步推理。
循环while 包裹上述过程，加 max_iter 上限（防死循环）和停止条件（如模型说了 FINISH 或达上限）。

2. 完整代码（在 step1.php 基础上改）

保存为 step2.php，填 key，跑 php step2.php：

// step2.php — Agent 循环骨架（PHP 原生，零依赖）
<?php

$API_KEY = 'sk-your-key-here';
$API_URL = 'https://api.deepseek.com/v1/chat/completions';
$MODEL   = 'deepseek-chat';

$GOAL = '我想了解巴黎，请分 3 个方面介绍（历史、美食、交通），每条一句话。最后用 FINISH 结束。';
$MAX_ITER = 6;  // 最多迭代 6 轮，防死循环/账单失控

// messages 是「对话历史」
$messages = [['role' => 'user', 'content' => $GOAL]];

for ($i = 0; $i < $MAX_ITER; $i++) {
    echo "\n═══ 第 " . ($i + 1) . " 轮 ═══\n";

    // 调用 LLM（同 step1）
    $ch = curl_init($API_URL);
    curl_setopt_array($ch, [
        CURLOPT_POST           => true,
        CURLOPT_HTTPHEADER     => [
            'Content-Type: application/json',
            'Authorization: Bearer ' . $API_KEY,
        ],
        CURLOPT_POSTFIELDS     => json_encode([
            'model'    => $MODEL,
            'messages' => $messages,   // 发送完整历史
            'max_tokens' => 256,
        ]),
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_TIMEOUT        => 30,
    ]);

    $body   = curl_exec($ch);
    $status = curl_getinfo($ch, CURLINFO_HTTP_CODE);
    curl_close($ch);

    if ($status !== 200) { echo "API 错误 HTTP $status\n" . $body; break; }

    $data  = json_decode($body, true);
    $reply = $data['choices'][0]['message']['content'];
    echo "模型：" . $reply . "\n";

    // 把模型回复追加到历史
    $messages[] = ['role' => 'assistant', 'content' => $reply];

    // 停止条件：模型说了 FINISH
    if (str_contains($reply, 'FINISH')) {
        echo "\n✅ Agent 完成（自报 FINISH）\n";
        break;
    }
}

echo "\n📊 总共跑了 " . ($i + 1) . " 轮，最终消息数：" . count($messages) . "\n";

运行输出大概是：

═══ 第 1 轮 ═══
模型：好的，让我从历史开始介绍。巴黎起源于...

═══ 第 2 轮 ═══
模型：接下来是美食方面。巴黎以... FINISH

✅ Agent 完成（自报 FINISH）
📊 总共跑了 2 轮，最终消息数：3

3. 循环里发生了什么（Observe→Think→Act 的 PHP 版）

$GOAL用户目标，作为第一条 user message。对 Agent 来说这就是「任务」。
$messages对话历史数组。每轮把模型回复 push 进去，下一轮原样发送。模型就是靠这个「记住」之前说了什么——messages 是 Agent 的短期记忆。
for 循环replace 了第 1 课的「调一次就结束」→ 每轮：调 LLM → 取回复 → push 历史 → 检查是否 FINISH → 继续或退出。
MAX_ITER安全阀。永远不要写无限循环——LLM 可能一直不说 FINISH。设合理上限（5-10），超过强制停止。
FINISH简陋但有效的「停止协议」。真正的 Agent 靠 stop_reason（API 返回的终止原因）判断，但这节课要你先理解原理。
PHP 工程师直觉：这和你写分页查询的 while 循环几乎一样——while($hasMore && $page < $maxPages){ fetch($page); $page++; }。区别只在于：每次 fetch 的不是数据库，是 LLM；翻页信号不是 rowCount=0，是模型说了 FINISH。

4. 动手：改 GOAL，看 Agent 怎么跑

把 $GOAL 换成下面任意一个，重新跑：

  • '用 3 句话总结 PHP 8.0 最重要的新特性，最后说 FINISH'
  • '你是一个客服，用户问"怎么退款"。按步骤回答，最后说 FINISH'
  • '写一首 4 行诗，主题是代码，每行之后分析一下为什么这么写，最后说 FINISH'

观察：同一个循环，换一个 GOAL，Agent 的行为完全不同。这就是 Agent 的核心——目标是变量，循环是骨架。
