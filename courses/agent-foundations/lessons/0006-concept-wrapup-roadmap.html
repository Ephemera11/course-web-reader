课程 0006 · 概念收官：手搓最小 Agent 路线图

Agent Foundations · 概念层收官 · 预计 7 分钟

五节课，你建立了从「Agent 是什么」到「复杂度光谱选型」的完整心智模型。这一课做两件事：① 把五课压缩成一张可随时查阅的概念地图；② 给你一个能直接开工的「手搓 Agent」最小骨架路线图——概念收官，准备动手。

1. 前五课压缩：一张概念地图

0001 · Agent 到底是什么
Agent = LLM + 工具 + 记忆 + 循环。它和普通 LLM 调用的本质区别在于： 模型不是一轮"问→答"，而是不断地 Observe→Think→Act→Observe 自驱循环。PHP 类比：相当于一个 while 循环里 LLM 自己决定每次迭代该调哪个函数、传什么参。
0002 · Agent 循环解剖 + 范式图谱
主流范式 = ReAct（推理+行动交替）；核心四阶段 = 感知 → 推理 → 行动 → 观察。范式本质是"控制权分配"——把多少决策权交给模型 vs 写死在代码里。
0003 · Tool Calling
工具 = 带 JSON Schema 的 API 端点。三要素：name（匹配）/ description（给模型的提示词）/ input_schema（约束参数）。description 打磨投入 = 主提示投入。
0004 · 五种 Workflow 范式
Chaining（流水线）→ Routing（分发）→ Parallel（扇出汇总）→ Orch-Workers（动态拆解）→ Eval-Opt（评审闭环）。每一种都是"预先定义控制流"——Workflow 可控可测，是 Agent 的前提。
0005 · 复杂度光谱：选型决策
能简单就别复杂。决策顺序 = Q1 Prompt → Q2 Chaining → Q3 Routing → Q4 Parallel → Q5 Orch-Workers → Q6 Agent。每往右一步，延迟↑/成本↑/不可控性↑。Agent 是最后手段，不是勋章。

2. 路线图：手搓最小 Agent（5 步迭代）

以下路线按"增量交付"设计——每一步都是可运行的小胜，不必一步到位。语言待你选（PHP 还是 Python），但骨架语言无关。

①
单轮 LLM 调用
能发一条 message、收到一条回复。这是地基——没有它就没有 Agent。
②
加循环框架
while + max_iter + stop 条件。模型不再是"一问一答"，而是"多轮自主推进"。
③
接一个工具
先只接一个最简单的工具（如 get_time() 或 echo()），打通"模型决定调→你执行→结果喂回"。
④
接两个工具 + 选路
两个工具让模型自己选。这一步验证了"调不调、调哪个、传什么参"三个决策。
⑤
加记忆 + 收束
把对话历史持久化、加前缀/系统提示词，让 Agent 在多次交互中保持上下文。

3. 每一步的"验收标准"（你才算真做完了）

① 单轮调用能跑通一次 model("你好")→"你好！"。用你选的语言+API provider，命令行能跑即可。验收：curl 一下或跑个脚本，看到回复。
② 循环给模型一个目标（如"查天气"），它能在循环里推进——即使只是说着"我需要工具"然后停。验收：日志里能看到 ≥3 轮迭代。
③ 一个工具定义 get_time 工具（返回当前时间字符串），Agent 被问"现在几点"时能正确调用并回复时间。验收：你问时间→Agent 回实际时间。
④ 两个工具同时注册 get_time 和 calculator(expr)，Agent 被问"3小时后是几点"能先算时间再调工具。验收：两步都正确。
⑤ 记忆关闭进程再重启，Agent 记得上一轮对话的内容。验收：先问"我叫张三"，重启后问"我叫什么"，答"张三"。

4. 技术选型建议（两条路）

根据你的 PHP 背景，两条路都走得通——关键是先跑起来，别在选型上花太多时间：

路线 A：纯 PHP（你的主场）
用 guzzlehttp/guzzle 调 OpenAI/Claude API，while 循环在 CLI 脚本里跑。
优点：零新语言开销，直接复用 cURL/JSON/异常处理经验。
缺点：PHP 的 long-running 循环 + 异步不够原生（但对最小 Agent 够用）。
路线 B：Python（社区最热）
用 httpx 或 openai SDK，Python 脚本在终端跑。社区例子最多、调试工具最全。
优点：LLM/Agent 生态 99% 的教程用 Python，抄作业最快。
缺点：你需要切语言习惯（但你后端底子在，1-2 天适应）。
我的建议：先用你最熟的 PHP 跑通①②（单轮调用 + 循环骨架），这最多一个下午。到③④（工具调用、选路）时再评估——如果 PHP 写得顺手就继续，觉得别扭就切 Python。关键是先有能跑的东西，再决定要不要换语言。
